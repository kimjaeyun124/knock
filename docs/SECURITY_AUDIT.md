# 오류 처리·보안 점검 (2026-11-18)

이 서비스는 **실제 위험 상황의 감지를 보장하는 안전 인증 제품이 아닙니다.** 그래서 이 점검에서 가장 중요하게 본 것은 "공격을 막는 것"만큼 **"동작하지 않는 상황을 보호자에게 숨기지 않는 것"** 입니다. 코드·테스트를 직접 읽고 실행해 확인했고, 확인하지 못한 것은 그렇게 적었습니다.

## 확인한 것 (범위별)

### Frontend
- **API 요청 오류·잘못된 서버 응답**: 응답을 공유 Zod 스키마로 검증하고(계약과 다르면 오류), 오류 종류(연결 안 됨·시간 초과·401·403·404·429·5xx)를 한국어 문구와 해결 방법으로 통일(`apiErrors`). 가짜 성공·낙관 갱신 실패 시 되돌림.
- **Socket.IO 끊김**: 연결 상태를 헤더·알림 배지·연결 안내가 한 곳에서 계산한 값으로 표시, 끊긴 동안은 "마지막 확인" 문구, 재연결하면 REST 로 놓친 것을 보충.
- **페이지 로딩 실패·Error Boundary**: 모든 경로에 라우터 `errorElement`(`RouteErrorPage`)가 있어 화면 렌더링 오류·코드 분할 파일 로딩 실패(네트워크 끊김)도 안내와 다시 시도를 보임. (클래스형 Error Boundary 는 따로 두지 않았습니다 — 라우터가 그 역할을 합니다.)
- **접근 권한 오류**: 403·404 화면, 보호된 경로는 로그인 전에 화면을 그리지 않음.
- **오래된 데이터 표시**: 위 시험 3·10.
- **입력 검증**: 서버와 같은 규칙(공유 스키마)으로 검증하고 서버도 다시 검증.

### Backend
- 입력 검증(Zod, 본문 100KB 제한), 인증(HttpOnly·SameSite 쿠키, 운영에서 Secure, 세션 14일·로그아웃·재로그인 무효), 로그인 시도 제한(IP+이메일당 15분 5회), 비밀번호 scrypt 해시(파라미터 저장·상한 검사), 데이터 접근은 항상 세션의 가구 ID 로 한정, **CSRF**: 쓰기 요청은 허용된 웹 출처만(`same-origin` 가드 + `sec-fetch-site`), **CORS**: REST 는 같은 출처 배포를 전제로 별도 CORS 를 열지 않았고(`cors` 미사용) 소켓만 허용 출처 1개로 제한, **보안 헤더**: helmet + 운영 빌드 CSP(E2E `csp.spec`) + `x-powered-by` 제거, **환경변수 검증**: 시작 시 Zod 로 검증하고 잘못되면 서버를 띄우지 않음(VAPID 는 모두 있거나 모두 없어야 함), 예외 처리: 내부 오류 세부 미노출·`unhandledRejection`/`uncaughtException`·SIGTERM 정리.
- **로그의 민감정보**: pino `redact`(password·token·deviceToken·authorization·cookie·auth·p256dh·privateKey 등)로 가림, 4xx 는 스택 없이 한 줄. 요청 본문은 로그에 남기지 않음. 수신 오류도 **이유 코드만** 저장하고 본문은 저장하지 않음.
- 비밀값이 브라우저에 가지 않음: 빌드 후 `scripts/check-client-bundle.mjs` 가 서버 전용 키·실제 `.env` 값·Mock 표식이 웹 번들에 있으면 실패시킴. `VITE_` 변수에 비밀처럼 보이는 이름도 막음.
- 의존성: `npm audit --omit=dev` — 취약점 0건(2026-11-18 실행 시점 기준).

### Database
- **무결성**: 하위 테이블은 가구(또는 보호자)에 연결되고 삭제는 `onDelete: Cascade`(센서 삭제 시 알림의 센서 연결은 `SetNull`), 센서·장치 번호는 가구 안에서 유일, **이벤트는 (센서, 장치 이벤트 ID) 유일 제약으로 중복 저장이 불가능**.
- **인덱스**: 목록·필터의 주 경로(가구+시각, 가구+분류+시각, 센서+시각, 알림 가구+상태+시각, 전달 상태+다음 시도, 세션 만료)에 있음.
- **트랜잭션**: 계정 생성(동시 요청 시 한쪽만), 시뮬레이션 데이터 삭제, 센서 상태 변화 선점(`updateMany` 조건부)에 사용.
- **삭제 정책**: 보관 기간(기본 90일)이 지난 움직임 기록·종료된 알림·상태 이력을 주기적으로 정리, 시뮬레이션 데이터만 따로 삭제 가능(실제 데이터는 그대로 — 시험으로 확인), 만료 세션 정리.
- **데이터 중복**: 같은 이벤트·같은 푸시 구독(엔드포인트 유일)·같은 알림(`dedupeKey` 로 반복 억제 시간 안에는 새 알림 대신 근거만 추가)이 중복되지 않음.

### Realtime
- 소켓은 **로그인한 보호자만** 연결(쿠키 세션 + 출처 검사), 방(room)은 **서버가 세션의 가구로 정해 넣고** 클라이언트가 임의로 들어갈 수 없음, 클라이언트가 보낸 이벤트로 서버 상태를 바꾸지 않음(서버→클라이언트 방향만), 로그아웃하면 연결이 끊어짐, 재연결 후 REST 로 동기화, 이벤트 ID 로 중복 반영 방지(`socket.test.ts`, `realtime.flow.test.ts`, `realtime.spec`).

### Notification
- **중복 발송**: 같은 알림의 전달 기록은 보호자×채널당 하나, 반복 알림은 억제 시간 안에 새로 만들지 않음, 확인·종료된 알림의 남은 재시도는 `CANCELLED`.
- **발송 실패**: 최대 3회(30초·2분), 실패하면 기록하고 **모든 채널이 실패하면 "전달하지 못했습니다" 긴급 알림을 한 번** 만들어 상단 띠에 표시(숨기지 않음).
- **구독 만료**: 푸시 서비스가 404/410 으로 답하면 그 기기를 목록에서 지우고(이번 수정으로 재시도도 하지 않음), 일시 오류로는 지우지 않음.
- **전송 상태 기록**: 대기·전송 시도·전송 성공(앱 화면)·**전달 확인 불가(푸시 서비스에 넘겼을 뿐 기기 도착은 모름)**·전송 실패, 연동 안 된 채널은 "연동되지 않음". 푸시 서비스가 접수했다고 해서 도착했다고 표시하지 않습니다.
- **구독 해제·푸시 엔드포인트 검증**: 푸시 서비스 주소는 https 도메인만(IP·localhost·사설 이름 거부), 보호자당 기기 10개 제한, 내용에 센서 ID 등 내부 정보 없음.

| 5 | SQLite 파일 1개, 백업은 설정해야 함 | 중간(일부 완화) | 서버 내장 자동 백업(`BACKUP_DIR`)을 추가했습니다 — 무결성 검사를 통과한 사본만 남기고, 실패·오래됨·꺼짐을 설정 → 데이터 관리에 알립니다([OPERATIONS.md](OPERATIONS.md) 6절). 그러나 **기본은 꺼져 있고**, 같은 디스크에 두면 디스크 고장에는 소용없으며, 사본을 다른 기기로 옮기는 것과 **복구 연습은 운영자의 몫**입니다(여기서 복구 절차를 실제 운영 환경에서 시험하지는 못했습니다. 시험에서는 백업 파일을 다시 열어 데이터를 읽는 것까지 확인). 복구 전 점검용 `npm run backup:verify` 도 추가). |
| 6 | 외부 채널의 **도착은 확인할 수 없음** | 구조적 | 푸시 서비스가 접수해도 기기에 도착·표시되었는지는 알 수 없고(그래서 "전달 확인 불가"), 실제 푸시 서비스로 기기에 도착하는 것까지는 이 개발 환경에서 확인하지 못했습니다. 문자·카카오·스마트워치는 연동하지 않았습니다. |
| 7 | 푸시 서비스 주소의 DNS 재바인딩 | 낮음 | https 도메인만 받지만 이후 내부 IP 로 바뀌는 경우는 막지 못합니다. |
| 8 | 규칙의 정확도는 **검증되지 않음** | 구조적 | 감지 기준값은 시뮬레이터로 맞춘 초기값이며 현장 데이터로 검증하지 않았습니다. 서비스는 낙상·실종을 판정하지 않으며 화면도 그렇게 안내합니다. |
| 9 | 센서 시계가 틀리면 발생 시각이 어긋남 | 낮음 | 24시간 넘게 오래된·1분 넘게 미래인 시각은 거부하지만 그 안의 오차는 받아들입니다(지연 수신으로 표시). |
| 10 | 실제 스크린리더·실기기 점검 안 함 | 낮음 | 접근성은 자동 점검(axe)·키보드 점검까지만 했습니다. |
| 11 | **알림 영상(시연용 웹캠)이 서버에 저장됨** | 중간 | 사용자 요청으로 "알림에 영상 첨부"를 넣었고 **기본 켜짐**입니다. 알림이 새로 만들어진 순간의 약 4초만 저장하고(알림이 안 된 움직임은 저장 안 함), 로그인한 같은 가구만 볼 수 있으며(다른 가구 404, `no-store`), 7일 뒤 자동 삭제·알림 삭제 시 함께 삭제됩니다. 그러나 영상은 **DB 안에 암호화 없이** 저장되어 **백업에도 들어가고**, 화면에 사람이 비치므로 개인정보입니다. 시연 서버에서만 동작합니다(운영에서는 경로 없음). 실제 서비스에 쓰려면 동의 절차·암호화·접근 기록이 필요합니다. |

## 점검하지 않은 것

침투 시험(외부 공격 시도), 부하 시험(요청 제한 수치는 정상 사용 규모를 가정한 값입니다), 실제 하드웨어·실기기 푸시, 호스팅 환경(리버스 프록시·TLS 설정)의 실제 구성은 점검하지 못했습니다.
