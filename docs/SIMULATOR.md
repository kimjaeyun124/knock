# 센서 시뮬레이터

실제 하드웨어가 없어도 **센서 신호 수신 → 서버 검증 → DB 저장 → 감지 규칙 → 알림 생성 → Socket.IO → 화면 갱신**의 전체 흐름을 시험하고 시연하는 개발자·시연 전용 도구입니다. 화면은 `/dev/simulator`(설정 → 센서 시뮬레이터), 서버 API는 `/api/dev/simulator`, 명령줄 도구는 `npm run sim`입니다.

## 실제 처리 경로를 그대로 씁니다

```
시뮬레이터(서버) ──HTTP, 장치 토큰──▶ POST /api/ingest/v1/events · /heartbeat   (실제 센서와 같은 수집 API)
   → 토큰 인증 → 이벤트 검증(형식·시각·중복) → DB 저장 → 감지 규칙 → 알림 생성·전달 → Socket.IO → 대시보드 갱신
```

- `SimulatorService`는 **서비스 내부 함수를 직접 부르지 않고** 자기 서버의 수집 API를 HTTP로 부릅니다. 시뮬레이터로 확인한 경로가 곧 실제 센서의 경로입니다. (`modules/simulator/*.test.ts`가 임시 포트의 실제 서버로 확인)
- 버튼은 화면만 바꾸지 않습니다. 버튼 → 서버 API → 수집 API → DB의 순서로 처리되고, 화면의 "전송 결과"는 **서버가 돌려준 응답**(저장됨·중복·거부, 새로 생긴 알림)입니다.
- 만든 센서·기록·알림은 모두 `origin = SIMULATED`로 저장되어 화면 어디서나 **"시뮬레이션"** 으로 표시되고, 실제 센서의 신호와 섞어 판단하지 않습니다. 설정 → 데이터 관리에서 한 번에 지울 수 있습니다.

## 기능

| 요청한 기능 | 구현 |
|---|---|
| 1 가상 센서 생성 | "시뮬레이션 센서 만들기"(세 구역 모두) 또는 구역마다 "이 구역에 센서 만들기" (`POST /sensors {zone?}`) |
| 2 연결/해제 | 만들기 = 연결(첫 신호 전송, 이후 30초마다 heartbeat). **"연결 해제"** = 그 시뮬레이션 센서와 기록을 삭제(확인 대화상자, `DELETE /sensors/:zone`). 실제 센서는 건드리지 않음 |
| 3 센서 위치 설정 | 센서는 **구역**(침대 주변·이동 경로·현관)에 만들며, 구역이 곧 위치입니다. (구역당 한 개. 위치를 옮기려면 해제하고 다른 구역에 만듭니다) |
| 4 움직임 발생 | "움직임 보내기" — **이벤트 유형(전송 방식)** 을 고릅니다: 1건 / 반복(2~20건을 한 번에) / 중복(같은 이벤트 ID를 두 번) |
| 5 배터리 | 90·18·9% 버튼과 **직접 입력(0~100%)**. 서버가 "배터리 부족·위급" 기준으로 판단해 알림을 만듭니다 |
| 6 연결 끊김 | "연결 끊기" = 신호만 멈춤(서버는 설정한 시간, 기본 5분이 지나야 끊김으로 판단). **"끊김 바로 확인"** = 신호가 오래 없었던 것처럼 마지막 신호 시각을 기준 뒤로 돌리고 서버의 **실제 연결 점검 함수**를 바로 실행(기다림 단축용. 알림은 실제 점검 경로가 만듦) |
| 7 연결 복구 | "연결 복구" — heartbeat 재전송 → 끊김 알림 자동 종료 + "연결 복구" 정보 알림 |
| 8 반복 움직임 | 반복 전송(같은 구역 여러 건) + 시나리오 "짧은 시간 동안 여러 구역의 움직임"(구역 전환 횟수 기준) |
| 9 야간 이벤트 | **"가장 최근의 야간 시간으로 보내기"**: 낮에도 야간 규칙을 시험하도록, 발생 시각을 과거의 야간(모니터링 일정에 든 시각, 최대 23시간 전)으로 실어 보냄. 서버는 "늦게 도착한 신호"로 표시하되 발생 시각으로 규칙을 판단. 지금이 야간이면 그냥 지금 보냄. 야간이 없으면(모니터링 끔 등) 409로 이유를 알림 |
| 10 중복 이벤트 | 중복 전송 — 첫 번째 `ACCEPTED`, 두 번째 `DUPLICATE`로 표시되고 DB에는 한 건만 저장 |

## 화면(`/dev/simulator`)

| 구성 | 내용 |
|---|---|
| 가상 센서 목록 · 센서 선택 | 구역별 카드(연결 상태·배터리·신호 중단 표시) |
| 이벤트 유형 선택 | 전송 방식 선택, 반복 건수, "야간으로 보내기" |
| 움직임 발생·배터리 조절·연결 상태 변경 | 카드의 버튼과 입력 |
| **전송 결과 표시** | 가장 최근 전송의 서버 처리 결과: 저장됨·중복·거부·수신, 보낸/발생 시각, **이 전송으로 새로 만들어진 알림** (전송 전후의 알림 목록 비교). 실패하면 이유 |
| **최근 전송 이벤트 기록** | 최근 30건(최신순). 서버 메모리에만 보관되어 서버를 다시 켜면 비워짐 |
| 시나리오 재생 | A~E 포함 6종, 배속 1×·10×·60× (단계 사이 기다림만 줄임) |
| 장애 주입 | 시뮬레이션 알림의 앱 화면 전달 실패 |

### 예시 시나리오
| 요청 | 방법 |
|---|---|
| A 침대 주변 움직임 | 침대 주변 카드의 "움직임 보내기" (민감도 높음이면 알림, 아니면 기록) · 시나리오 "침대 주변에서 이동 경로로 이어진 움직임" |
| B 현관 움직임 | 현관 카드의 "움직임 보내기" · 시나리오 "현관 근처 움직임" → 즉시 확인 권장 알림 |
| C 센서 연결 끊김 | "끊김 바로 확인" (또는 "연결 끊기" 후 기준 시간 대기) |
| D 배터리 10% | 직접 입력 10 → 적용 (위급 수준 알림) · 시나리오 "센서 배터리 소진과 연결 끊김" |
| E 짧은 시간 반복 | 시나리오 "짧은 시간 동안 여러 구역의 움직임" · 반복 전송 |

## 보안

- **개발·시연에서만 켜집니다.** `SIMULATOR_ENABLED`를 지정하지 않으면 개발에서는 켜지고 **운영(`NODE_ENV=production`)에서는 꺼집니다.** 꺼져 있으면 `/api/dev/simulator` 경로 자체가 없고(404와 같은 응답) 화면은 "시뮬레이터가 꺼져 있습니다"를 보입니다. (`env.test.ts`)
- **외부 사용자가 임의 이벤트를 만들 수 없습니다.** 모든 시뮬레이터 API는 로그인한 보호자의 세션과 허용된 출처(CSRF 방어)를 요구하고, 보호자 자신의 가구에만 센서를 만듭니다. 비로그인은 401, 다른 출처는 403입니다.
- 시뮬레이터가 만든 신호·알림은 `SIMULATED`로 구별되며, 앱 밖으로 나가는 채널(푸시 등)로는 보내지 않습니다.
- 운영에서 시뮬레이터를 켜지 마세요. 켜면 로그인한 보호자가 가짜 알림을 만들 수 있습니다.

## API (`/api/dev/simulator`, 모든 응답은 현재 시뮬레이터 상태 + `recent` 전송 기록)

| 요청 | 설명 |
|---|---|
| `GET /state` | 상태 |
| `POST /sensors` `{zone?}` | 센서 만들기 |
| `DELETE /sensors/:zone` | 연결 해제(삭제) |
| `POST /motion` `{zone, mode?, count?, when?}` | 움직임 전송. `mode` single·burst·duplicate, `count` 2~20, `when` now·night |
| `POST /battery` `{zone, batteryPercent}` | 배터리 보고 |
| `POST /silence` `{zone, silenced, fastForward?}` | 연결 끊김/복구 |
| `POST /faults` `{deliveryFailure}` | 전달 실패 주입 |
| `POST /scenarios/:id/run` `{speed}` · `POST /scenarios/stop` | 시나리오 |

## 웹캠 입력

버튼 대신 노트북 카메라의 움직임으로 신호를 보내는 화면(`/dev/webcam`)이 있습니다. 같은 `POST /api/dev/simulator/motion` 을 쓰므로 처리 경로와 "시뮬레이션" 표시는 그대로입니다. 영상은 브라우저 밖으로 나가지 않습니다. [WEBCAM_MOTION.md](WEBCAM_MOTION.md)

## 시연 보조 명령

`npm run sim -- demo reset` 은 **시뮬레이션 데이터만** 지우고 세 구역의 시뮬레이션 센서를 다시 연결하며(실제 데이터는 건드리지 않고 남은 수를 보여 줌), `demo status` 는 상태만 보여 줍니다. 시연 방법은 [DEMO_GUIDE.md](DEMO_GUIDE.md). 시뮬레이션 데이터가 서버에 있으면 모든 화면 위에 "실제 상황이 아님" 띠가 보입니다.

## 한계

- 구역당 시뮬레이션 센서는 한 개입니다. 같은 구역에 여러 개를 만들거나 센서를 다른 구역으로 옮기는 기능은 없습니다.
- "끊김 바로 확인"은 시간을 건너뛰는 시연용 단축입니다(마지막 신호 시각을 직접 고침). 실제 센서의 끊김과 같은 경로는 "연결 끊기" 후 기준 시간(기본 5분)을 기다리는 방법입니다.
- 전송 기록은 서버 메모리에만 있습니다. 알림·움직임 기록은 DB에 남습니다.
- 실제 센서 하드웨어의 동작(전파 환경, 오탐·미탐)은 시뮬레이션으로 알 수 없습니다.
