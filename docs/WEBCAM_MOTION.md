# 웹캠 움직임 감지 (시연용)

노트북 카메라로 움직임을 찾아 **시뮬레이션 센서의 움직임 신호**로 보내는 시연 화면입니다. 설정 → 그 밖의 설정 → **웹캠 움직임 감지**(`/dev/webcam`)에 있습니다. 실제 센서가 없어도 "내가 움직이면 알림이 뜨는" 장면을 직접 보여 줄 수 있습니다.

> **이것은 실제 서비스의 센서가 아닙니다.** 시연 서버(`SIMULATOR_ENABLED`)에서만 열리고, 운영 서버에서는 화면과 경로가 없습니다. 신호는 모두 "시뮬레이션"으로 기록되며 앱 밖(푸시 등)으로 나가지 않습니다.

## 어떻게 동작하나

```
웹캠 → (브라우저 안) 64x48 흑백으로 줄임 → 앞뒤 화면 비교 → 움직임 확정
   → POST /api/dev/simulator/motion {zone, when} → 시뮬레이터가 수집 API 로 전송
   → DB 저장 → 감지 규칙 → 알림 → 실시간 화면
```

- **움직임 판단은 이 브라우저 안에서 합니다.** 서버로 가는 것은 "이 구역에서 움직임이 있었다"는 작은 JSON 신호입니다. 마이크는 쓰지 않습니다(`audio: false`).
- **알림 영상(v4, 기본 켜짐):** "알림이 생기면 그 순간의 영상(약 4초)을 함께 보내기"가 켜져 있으면, 움직임이 확정된 순간부터 4초를 브라우저에서 녹화(`MediaRecorder`, webm)하고, 그 신호로 **알림이 새로 만들어졌을 때만** 그 알림에 올립니다(`POST /api/dev/simulator/alerts/:id/clips`). 알림이 되지 않았거나 기존 알림에 합쳐진 신호의 영상은 **어디에도 저장하지 않고 버립니다.** 저장된 영상은 로그인한 같은 가구만 알림 상세 화면("알림과 함께 온 영상")에서 볼 수 있고(다른 가구 404, `Cache-Control: private, no-store`), **7일 뒤 자동 삭제**·알림이 지워지면 함께 삭제됩니다. 6MB·알림당 5개까지, 시뮬레이션 알림에만 붙습니다. 끄면 영상은 브라우저 밖으로 나가지 않습니다.
- 카메라는 "카메라 시작"을 눌렀을 때만 켜지고, "카메라 끄기"나 화면 이동·닫기에서 트랙을 멈춥니다.
- 움직임 판단(`apps/web/src/features/webcam/motionDetector.ts`): 화면을 가로로 나눈 **칸마다** 앞뒤 화면에서 밝기가 **40 이상** 달라진 칸의 비율을 구하고, 최근 일정 프레임 구간의 **평균**이 기준 이상이면서 구간의 절반 이상이 기준의 절반 이상일 때(= 잠깐 크게 바뀌고 끝난 변화가 아닐 때) 그 칸의 움직임으로 확정합니다. 확정 뒤 **같은 칸은 5초 동안 다시 보내지 않습니다**(서버 요청 제한 보호, 알림 폭주 방지). 신호를 보내는 중에 같은 구역이 또 확정되어도 쌓지 않고 건너뜁니다.

| 민감도 | 침대 주변 (엄격) | 이동 경로·현관 (예민, v4) |
|---|---|---|
| **낮음(기본)** | 평균 30% · 10프레임 ≈ 1.5초 | 평균 20% · 6프레임 ≈ 0.9초 |
| 보통 | 18% · 0.9초 | 12% · 0.6초 |
| 높음 | 10% · 0.6초 | 7% · 0.45초 |

- **구역별 기준(v4):** 침대 주변은 뒤척임을 거르려 엄격한 기준을 그대로 두고, 사람이 지나가는 이동 경로·현관은 사용자 요청으로 더 예민하게 했습니다. 현관·이동 경로 "낮음" 20% 는 실제 화면에서 가만히 앉아 손으로 얼굴을 만진 정도(17%)보다 조금 위입니다. 그래서 현관 칸에서는 0.45초 정도 지나가는 움직임도 잡힐 수 있습니다.

- **판정 강화(v3):** 처음 값(8%·4%·1.5%, 2프레임)은 너무 예민했고, 1차로 12%·7%·3.5%로 올린 뒤에도 **가만히 앉아 손으로 얼굴을 만지는 정도가 한 칸의 17% 안팎으로 잡혀** "움직임 6번"이 세어졌습니다(실제 화면 확인). 그래서 ① 밝기 변화 기준을 25 → 40 으로 올려 잡음·자동 밝기 조절을 거르고, ② 연속 프레임 수 대신 **구간 평균**으로 판단하며 기준을 30%·18%·10%로 올리고, ③ 순간 변화가 평균만 채우고 끝나는 것을 막는 **지속 조건**을 넣고, ④ 같은 칸의 재확정 대기를 3초 → 5초로 늘렸습니다. 기본은 가장 둔한 "낮음"입니다. 그래도 **뒤척임과 일어나는 움직임을 화면 변화만으로 정확히 구별할 수는 없습니다.** 그래서 화면을 구역으로 나눕니다.
- **3구역 나누기(기본):** 화면 왼쪽 = 침대 주변, 가운데 = 이동 경로, 오른쪽 = 현관(거울처럼 보이는 미리보기 기준)으로 보고 칸마다 따로 판단해 해당 구역의 시뮬레이션 센서로 신호를 보냅니다. 침대 칸 안에서만 움직이면 침대 주변 신호만 가고(기본 규칙에서는 알림 없이 기록만), 침대 칸에서 가운데·오른쪽 칸으로 이어지면 실제 센서 둘이 순서대로 반응한 것과 같게 "침대 → 이동 경로"(확인 필요), "현관"(즉시 확인 권장) 알림이 됩니다. "화면 전체를 한 구역으로"로 바꾸면 예전처럼 한 구역만 씁니다.

## 쓰는 법

1. `npm run dev` 로 실행하고 로그인합니다. (카메라는 `localhost` 또는 https 주소에서만 쓸 수 있습니다)
2. 설정 → 웹캠 움직임 감지를 엽니다.
3. **화면 나누기**(기본: 3구역)와 **민감도**(기본: 낮음)를 고릅니다. 한 구역으로 쓰려면 구역도 고릅니다.
4. 지금이 야간이 아니면 **"가장 최근의 야간 시간으로 보내기"** 가 처음부터 켜져 있습니다. (끄면 기록만 남고 알림은 만들어지지 않습니다) 화면의 **"이 화면의 움직임이 알림이 되는 경우"** 카드가 구역별로 알림이 되는지, 안 되면 이유가 무엇인지 알려 줍니다.
5. **카메라 시작**을 누르고 브라우저의 카메라 허용 창에서 허용합니다. 시작할 때 필요한 구역의 시뮬레이션 센서가 없으면 자동으로 만듭니다.
6. 카메라 앞에서 크게 움직이면 해당 칸에 "움직임이 보입니다"가 뜨고 신호가 갑니다. 대시보드·알림 센터가 새로고침 없이 바뀝니다. **알림은 이 노크 화면이 열려 있을 때 위쪽 배너로 뜨고, 소리는 헤더의 "알림 소리"를 켜야 납니다.**

발표 팁: 3구역 나누기에서 **왼쪽(침대 칸)에서 뒤척이면 기록만** 남고, **오른쪽으로 걸어 나가면** "침대 → 이동 경로"와 "현관" 알림이 뜹니다. "뒤척임은 알리지 않고 침대를 떠나 움직일 때 알린다"를 그대로 보여 줄 수 있습니다.

## 한계 (꼭 말할 것)

- **알림 영상은 개인정보입니다.** DB 안에 암호화 없이 저장되어 백업에도 들어갑니다. 시연에서 다른 사람이 비치지 않게 하고, 끝나면 설정 → 데이터 관리에서 시뮬레이션 데이터를 지우세요(영상도 함께 지워짐). 실제 서비스에 쓰려면 동의 절차·암호화·접근 기록이 필요합니다.
- 영상은 알림이 만들어진 **뒤**의 4초입니다. 움직임이 확정되기 전(그 직전) 모습은 들어 있지 않습니다.
- 푸시 알림에는 영상이 실리지 않습니다. 앱의 알림 상세에서만 볼 수 있습니다.
- 버그 수정(v4): 3구역에서 여러 칸이 거의 동시에 신호를 보내면 먼저 보낸 칸이 **첫 신호 뒤로 다시 보내지 못하던** 문제를 고쳤습니다(칸마다 따로 전송).

- **사람이 움직인 것과 그 밖의 화면 변화를 구분하지 못합니다.** 조명 변화, 카메라 자동 밝기 조절, 흔들림, 화면에 비친 움직임도 움직임으로 봅니다. 사람 인식·낙상·상태 판단을 하지 않습니다.
- 기준값(30%·18%·10%), 밝기 기준 40, 평균 구간, 5초는 **현장에서 맞춘 값이 아니라 데모용 초기값**입니다. 카메라 위치·거리·밝기에 따라 달라지므로 리허설에서 화면의 "변화 %" 막대를 보며 민감도를 맞추세요.
- 카메라 한 대의 화면을 가로 3칸으로만 나눕니다. 위아래나 그 이상으로 나누지 않습니다. 침대·복도·현관이 한 화면에 나란히 보이도록 카메라를 두어야 하며, 이것은 실제 집의 센서 배치를 대신하지 못합니다.
- 백그라운드 탭은 브라우저가 타이머를 늦춰 감지가 느려지거나 멈출 수 있습니다. 시연 중에는 이 탭을 앞에 두세요.
- 운영 서버 앞단에 두는 프록시 설정 예시([OPERATIONS.md](OPERATIONS.md) 7절)의 `Permissions-Policy: camera=()` 는 카메라를 막으므로, 그 설정에서는 이 화면이 동작하지 않습니다. 의도한 동작입니다.

## 검증

- 단위(`motionDetector.test.ts`, 24개): 흑백 변환, 변화 비율(경계·잡음·크기 불일치), 칸별 변화 비율, 연속 프레임·대기 시간·민감도 변경·초기화, **가만히 앉아 손짓하는 정도(칸의 17%가 9초간 계속 달라짐)는 확정하지 않음, 뒤척임·0.45초짜리 전체 화면 번쩍임도 확정하지 않음, 칸의 약 40%가 1.5초 이상 달라지면 확정, 확정 뒤 5초 대기**.
- 화면(`webcam.test.tsx`, 20개): 기본값(3구역·낮음), **침대 칸에서만 움직이면 침대 신호만, 현관 칸에서만 움직이면 현관 신호만(거울 상 기준)**, 짧은 변화는 전송 없음, 야간이 아니면 야간 옵션이 처음부터 켜짐, 알림 조건 카드(구역별 알림/기록만과 이유), 꺼져 있을 때 카메라를 건드리지 않음, 개인정보 안내와 금지 표현 검사, 마이크 없이 영상만 요청, 선택한 구역·야간 옵션으로 전송, 대기 시간 안 재전송 없음, 움직임이 없으면 전송 없음, 끄기·화면 이탈 때 트랙 정지, 권한 거부·카메라 없음·지원 안 됨 안내.
- E2E(`e2e/tests/webcam.spec.ts`): **Chrome 의 가짜 카메라**(판정이 엄격해진 뒤에는 기본 가짜 화면의 작은 변화가 잡히지 않아, 화면 전체가 검정↔흰색으로 크게 바뀌는 영상 파일을 만들어 가짜 카메라로 씀)로 실제 브라우저에서 시작 → 미리보기 입력 → 움직임 확정 → 서버의 시뮬레이션 이벤트·알림 생성 → 끄면 카메라 정지, 그리고 요청이 모두 로컬이고 2KB 미만임(영상 미전송)을 확인했습니다. 화면을 떠날 때 카메라 트랙이 멈추는 것도 확인했습니다.
- **진짜 웹캠과 진짜 사람의 움직임으로 실행한 시험은 하지 못했습니다.** 위 시험은 가짜 카메라(계속 변하는 테스트 화면)입니다. 실제 카메라에서의 감도는 직접 한 번 확인해 주세요.
