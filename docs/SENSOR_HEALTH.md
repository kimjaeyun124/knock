# 센서 상태 모니터링

센서가 정상적으로 동작하지 않는 상태(연결 끊김·배터리 부족·신호 없음·받지 못한 데이터)를 보호자가 빠르게 알 수 있게 합니다. 상태는 **DB에 저장된 마지막 신호 기록에서 그때그때 계산**하므로 서버를 다시 시작해도 그대로 복원됩니다.

## 모니터링 항목

| 항목 | 값·표시 | 어디서 정하나 |
|---|---|---|
| 연결 상태 | `PENDING`(첫 신호 전) · `ONLINE` · `OFFLINE` · `DISABLED`(사용 안 함) | 마지막 신호 시각 + 연결 끊김 기준 (`deriveSensorState`) |
| 마지막 통신 시각 | `lastSeenAt` — 움직임·heartbeat 어느 쪽이든 서버가 마지막으로 받은 때 | 수집 API 수신 시 갱신 |
| 마지막 heartbeat | `lastHeartbeatAt` — **heartbeat(상태 보고)만** 기록. 움직임 신호는 통신 시각만 갱신 | `POST /api/ingest/v1/heartbeat` |
| 배터리 | `batteryPercent` + `batteryLevel`(`OK`·`LOW`·`CRITICAL`·`UNKNOWN`) | 센서가 보고한 값. **보고하지 않으면 `UNKNOWN`이고 잔량을 만들어 내지 않는다** |
| 비활성 여부 | `isActive=false` → `DISABLED`. 신호를 받지 않고(403) 끊김·배터리 알림도 만들지 않음 | 센서 상세의 "사용" 스위치 |
| **데이터 수신 오류** | `receiveErrors { count, lastAt, lastReason }` — 서버가 받지 못한 데이터의 누적 횟수·마지막 시각·이유 | 아래 참고 |
| **장시간 미응답** | `silentSeconds`(마지막 통신 후 경과 초), `longSilent`(끊긴 채 1시간 이상) | 계산값 (`LONG_SILENT_SECONDS`) |

연결 상태와 배터리는 **서로 독립**입니다. (연결됨 + 배터리 부족, 연결 끊김 + 배터리 충분 모두 그대로 표시)

## Heartbeat

센서는 `POST /api/ingest/v1/heartbeat`로 상태를 주기적으로 보냅니다(장치 토큰 인증, 본문은 선택: `batteryPercent` 0~100, `firmware`). 본문이 없어도 됩니다(배터리 정보가 없는 장치). 서버는 마지막 heartbeat 시각을 저장하고, 신호(움직임 포함)가 **설정한 시간 동안 없으면** 연결 끊김(OFFLINE)으로 봅니다. 계약 전체는 [INGEST_CONTRACT.md](INGEST_CONTRACT.md).

### 타임아웃 (실제 센서의 통신 특성에 맞춤)

- 기본: 설정의 "연결 끊김 기준"(기본 5분, 1~60분) — 가구의 모든 센서에 적용.
- **센서별**: 센서 상세 → "연결 끊김 기준"에서 그 센서만 다른 값을 정할 수 있습니다(1~60분). 신호 간격이 긴 배터리 센서용입니다. 비우면 가구 기본을 따릅니다. (`Sensor.offlineAfterSeconds`, 응답의 `effectiveOfflineAfterSeconds`가 실제 적용값)
- 판단은 연결 상태 계산·끊김 점검·수신 처리·시뮬레이터가 모두 같은 함수(`effectiveOfflineAfterSeconds`)를 씁니다.

## 연결 끊김과 복구

```
신호가 기준 시간 동안 없음 → (30초마다 주기 점검) 끊김 이력 DISCONNECTED 기록 + SENSOR_OFFLINE 알림 + sensor.status 실시간 전달
신호가 다시 옴            → ONLINE, 이력 CONNECTED(복구) 기록 + 끊김 알림 자동 종료 + SENSOR_RESTORED 정보 알림
```
- 끊김 이력·알림은 **한 번만** 만들어집니다(점검을 되풀이해도, 서버를 다시 시작해도).
- 처음 연결(PENDING→ONLINE)은 복구가 아닙니다. 한 번도 신호가 없는 센서는 끊김 알림이 없습니다.
- 그 구역의 유일한 활성 센서가 끊기면 긴급, 다른 센서가 더 있으면 주의입니다.

## 배터리

- 임계값은 설정(기본: 부족 20% · 위급 10%)에서 바꿉니다. 바꾸면 그 기준으로 바로 판단합니다.
- **임계값 이하로 처음 들어갈 때** 알림이 만들어지고(부족=참고, 위급=주의), 같은 수준이 반복 보고되어도 **다시 알리지 않습니다**(상태 이력도 수준이 바뀔 때만). 위급으로 악화되면 같은 알림이 승격됩니다. 회복하면 자동 종료되고, 다시 내려가면 새 알림입니다.
- 센서가 배터리 값을 보내지 않으면 `UNKNOWN`(화면: "알 수 없음")입니다. 보고하지 않은 값을 임의로 채우지 않고, heartbeat에 값이 없다고 이전 값을 지우지도 않습니다.

## 비정상 데이터 처리

| 상황 | 처리 | 수신 오류로 기록 |
|---|---|---|
| 발생 시각이 24시간보다 오래됨 / 서버 시각보다 1분 넘게 미래 | 이벤트 거부(`REJECTED`: `TOO_OLD`·`FUTURE_TIMESTAMP`), 저장 안 함 | O |
| 이 센서가 보낼 수 없는 신호 종류 | 거부(`TYPE_MISMATCH`) | O |
| 형식이 틀린 요청(범위 밖 배터리 -3·150, 빈 이벤트 목록, 짧은 이벤트 ID, 숫자가 아닌 값) | 400, **값을 바꾸지 않음**(배터리가 잘못된 값으로 덮어써지지 않음) | O (`INVALID_PAYLOAD`) |
| 같은 이벤트 ID 재전송 | `DUPLICATE`, 저장·알림 없음 | **X** (정상 동작) |
| 틀린 토큰 | 401 | X (어느 센서인지 알 수 없음) |

수신 오류에는 **이유 코드만** 남기고 요청 본문은 저장하지 않습니다. 거부된 신호도 "센서가 살아 있다"는 뜻이라 연결 상태는 ONLINE으로 유지됩니다. 최근 1시간 안의 오류는 화면이 주의 색으로, 그보다 오래된 것은 기록으로만 보여 줍니다.

## 화면

| 화면 | 표시 |
|---|---|
| 센서 관리(목록) | 연결·배터리 배지, 마지막 통신, **장시간 미응답 경고**, **데이터 수신 오류 N건·마지막 이유**, 목록 위 요약(끊긴 센서·1시간 넘게 신호 없는 센서·배터리 부족·최근 수신 오류) |
| 센서 상세 | 위 항목 + 마지막 heartbeat, 적용 중인 연결 끊김 기준(가구 기본/센서별), 배터리 값 또는 "알 수 없음", **센서별 연결 끊김 기준 저장**(실패하면 이전 값으로 되돌리고 이유 표시) |
| 대시보드 센서 카드 | 구역별 센서의 연결·배터리·마지막 신호와 같은 경고 |
| 실시간 | 상태가 바뀌면 `sensor.status`·`monitoring.status`로 두 화면이 **새로고침 없이** 갱신, 끊긴 연결은 다시 연결될 때 REST로 맞춤([REALTIME.md](REALTIME.md)) |

## 시뮬레이터로 확인

`/dev/simulator`([SIMULATOR.md](SIMULATOR.md))에서 구역 카드의 **끊김 바로 확인 → 연결 복구**, **배터리 18%/9%/직접 입력**, 전송 방식 **"잘못된 신호"**(25시간 전 발생으로 보내 서버가 거부하는지 시험)를 실행하면 서버 상태와 센서 관리·대시보드 화면이 같은 값을 보입니다.

## 서버 재시작 후 복원

센서 상태·끊김 이력·알림은 모두 DB에 있고 연결 상태는 마지막 신호 시각에서 계산하므로, 재시작 직후에도 같은 상태가 나오고 주기 점검이 이어서 동작합니다(이미 만든 끊김 이력·알림은 다시 만들지 않음 — 테스트로 확인). 단, 시뮬레이터의 "신호를 보내지 않는 중" 같은 **메모리 상태**는 재시작하면 사라집니다(시뮬레이터 센서가 다시 heartbeat를 보냄).

## 한계

- 수신 오류는 횟수·마지막 이유만 저장합니다(내용·시각 이력은 없음). 알림은 만들지 않고 화면에 표시합니다.
- 장시간 미응답(1시간)은 표시용이며 별도 알림·재알림은 없습니다. 끊김 알림(긴급/주의)이 이미 열려 있습니다.
- 마이그레이션 이전의 센서는 `lastHeartbeatAt`이 비어 있습니다(다음 heartbeat부터 기록).
