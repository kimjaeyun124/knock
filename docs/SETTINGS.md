# 설정 화면

`/settings` 한 화면에 **모니터링 · 감지 · 알림 · 서비스** 네 구역이 있습니다. 모든 항목은 실제 동작과 이어져 있고, 동작과 무관한 장식용 스위치는 없습니다. 구역마다 자기 저장 단추가 있습니다.

## 원칙

- **저장은 기존 설정 API로**: 감지 설정 `PUT /api/settings/detection`, 받을 알림 `PUT /api/settings/alerts`, 센서별 민감도 `PATCH /api/sensors/:id`. 구역은 **바꾼 항목만** 서버의 최신 값에 덮어써서 보냅니다(다른 화면에서 바꾼 값을 되돌리지 않음).
- **저장 전 검증**: 화면에서 먼저(시각 형식·시작≠종료·숫자 범위·요일 1개 이상) 검증하고, 서버가 같은 규칙으로 다시 검증합니다.
- **저장 중 상태**: 저장하는 동안 단추가 잠기고 "저장하는 중…"이 보입니다.
- **저장 성공 피드백**: 서버가 저장을 확인한 뒤에만 "저장했습니다. (시각)"을 보입니다.
- **저장 실패는 성공으로 보이지 않습니다**: "저장하지 못했습니다. 서버에 반영되지 않았습니다. (이유)"를 알리고, 고친 값은 화면에 남겨 다시 시도할 수 있습니다.
- **새 값은 실제 이벤트 처리에 반영됩니다**: 저장한 설정은 서버의 규칙 엔진이 **다음 신호부터** 읽습니다(아래 표). 이미 처리된 신호를 다시 판단하지는 않습니다.

## 구역별 항목과 반영 위치

### 1. 모니터링

| 항목 | 저장 | 이벤트 처리에서 하는 일 |
|---|---|---|
| 모니터링 사용 | `monitoringEnabled` | 끄면 움직임 신호는 **기록되지만 움직임 알림은 만들어지지 않음** (`domain/time.ts#isMonitoredTime` → `movement-rules.ts`). 센서 연결·배터리 알림은 별개 |
| 요일별 일정 | `activeWeekdays` (0=월…6=일) | **야간 구간이 시작되는 날** 기준. 월요일만 고르면 월요일 밤 10시~화요일 새벽 6시가 해당 |
| 감지 시작·종료 시간 | `nightStart`/`nightEnd` | 이 시간대의 신호만 판단 (자정을 넘는 구간 지원) |
| 시간대 표시 | (읽기 전용) | 서비스 전체가 **한국 표준시로 고정**이라 바꿀 수 없다고 밝힘. 기기 시간대가 다르면 움직임 기록 화면의 시각이 달라 보일 수 있다고 안내 |

### 2. 감지

| 항목 | 저장 | 반영 |
|---|---|---|
| 기본 민감도(낮음/보통/높음) | `sensitivity` | 어떤 신호를 알림으로 만들지(규칙 표는 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) 10절) |
| **센서별 민감도** | `Sensor.sensitivity` (null = 기본 따름) | 그 센서의 신호에는 센서 값이 우선 (`RuleEvent.sensitivity`) |
| 반복 감지 처리 시간 | `sequenceWindowMinutes` | 침대 주변 → 이동 경로를 한 흐름으로 보는 시간 |
| 이벤트 판단 규칙 | (읽기 전용 설명) | 현재 설정 값(요일·시간·판단 시간·반복 기준)이 들어간 문장. 반복 기준은 서버와 같은 상수(`REPEATED_THRESHOLD`) |
| 감지 이벤트별 알림 여부 | `AlertPreferences` 4종 | 끈 종류는 알림을 만들지 않음(`AlertPipeline.raiseIfWanted`) |

**물리적 민감도와 서버 판단 민감도는 다릅니다.** 지금 지원하는 센서(HTTP로 신호를 보내는 움직임 센서)는 하드웨어 민감도 조절을 지원하지 않습니다(`Sensor.hardwareSensitivitySupported = false`, 서버가 내려 줌). 그래서 화면은 센서마다 *"하드웨어 민감도 조절을 지원하지 않습니다. 서버가 신호를 해석하는 기준만 바뀌고, 센서의 감지 감도는 그대로입니다."* 라고 표시합니다. 조절을 지원하는 센서가 생기면 이 값이 true로 내려오고 안내 문구가 바뀝니다.

### 3. 알림

| 항목 | 저장 | 비고 |
|---|---|---|
| 브라우저 알림 | 이 기기의 푸시 등록(서버) | 권한은 버튼을 눌렀을 때만 요청. 서버에 푸시 키가 없거나 브라우저가 지원하지 않으면 그렇다고 알림 |
| 소리 사용 | **이 기기(브라우저)** | 화면이 열려 있을 때 새 알림이 오면 짧은 소리. 헤더의 소리 스위치와 같은 값 |
| 주요 이벤트 알림 | (현관 근처 움직임의 상태를 보여 줌) | 종류별로 켜고 끄는 곳은 감지 구역 |
| 센서 장애 알림 | `sensorIssues` | 연결 끊김·복구 |
| 배터리 부족 알림 | `lowBattery` (새로 분리) | 이전의 "센서 이상" 하나가 배터리까지 껐으므로, 마이그레이션이 기존 값을 그대로 이어 받음 |
| 중복 알림 간격 | `cooldownMinutes` (1~120분) | 같은 종류의 신호를 새 알림 대신 기존 알림에 합치는 시간 |

### 4. 서비스 (이 기기에만 저장, 서버에 저장하지 않음)

| 항목 | 동작 |
|---|---|
| 화면 테마: 기기 설정 따르기 / 밝게 / 어둡게 | 즉시 적용·저장(`localStorage`). 첫 화면이 그려지기 전에 `public/theme-init.js`가 적용해 번쩍이지 않음. 어두운 테마 토큰은 `styles/tokens-dark.css`, 글자·테두리 대비는 `tokens-dark.test.ts`가 밝은 테마와 같은 기준(4.5:1·3:1)으로 검사 |
| 글자 크기: 보통 / 크게(115%) / 아주 크게(130%) | `<html data-text-size>` → 모든 글자가 rem이라 화면 전체가 함께 커짐. 브라우저 확대와 함께 쓸 수 있음 |
| 데이터 새로고침 | 자동(끔/30초/1분/5분): 화면이 보이고 인터넷이 연결된 때만 서버 데이터를 다시 읽음(`DevicePrefsEffects`). "지금 새로고침" 단추 |
| 시스템 연결 상태 | 인터넷·서버(버전)·실시간 연결·마지막 정상 시각, "연결 다시 확인" |

## 잘못된 설정으로 중요한 알림이 막히지 않게

설정 맨 위의 **"지금 설정에서 전달되지 않는 알림"** 요약(`overview/blocked.ts`, 순수 함수·단위 테스트 있음)이 현재 저장된 설정을 읽어 무엇이 전달되지 않는지 항목으로 알립니다.

| 수준 | 예 |
|---|---|
| **중요(위험)** | 모니터링 끔 · 요일을 절반 이상 뺌 · 현관 근처 움직임(즉시 확인 권장) 알림 끔 |
| 경고 | 다른 움직임 알림 끔 · 요일 일부 뺌 · 센서 장애/배터리 알림 끔 · 사용 중인 현관 센서 없음 |
| 참고 | 침대 주변 움직임은 민감도 '높음'에서만 만들어짐 · 이동 경로 센서가 '낮음' · 중복 알림 간격 60분 이상 |

- **중요한 알림이 새로 막히는 저장**(모니터링 끄기·현관 알림 끄기·요일 대부분 빼기)은 저장 전에 **한 번 더 확인**하고, 무엇이 전달되지 않는지 대화상자에 나열합니다.
- 알림을 끄는 모든 스위치 아래에 **끄면 무엇이 전달되지 않는지**와 **그래도 남는 것**(움직임 기록, 센서·대시보드의 상태 표시)을 적습니다.
- 알림 전달 실패 알림은 끌 수 없습니다.
- 이 요약은 "안전하다"고 말하지 않습니다. 모두 켜져 있어도 *센서가 놓치는 움직임은 알릴 수 없고, 알림이 없다고 괜찮다는 뜻이 아니라*고 밝힙니다.

## 하위 화면

| 경로 | 내용 |
|---|---|
| `/settings/detection` | 고급 기준(재알림 간격·연결 끊김·배터리 기준·기록 보관 기간). 모니터링 사용·요일은 저장된 값을 그대로 보냄 |
| `/settings/notifications` | 채널별 상태·테스트 발송·푸시 기기 목록 |
| `/settings/integrations` · `/settings/data` | 연동 현황 · 데이터 관리 |
