# 레이아웃과 라우팅

화면 전체의 틀(AppShell)과 주소 구조를 설명합니다. 코드는 `apps/web/src/app/`(주소·경로 정의)와 `apps/web/src/components/layout/`(틀)에 있습니다.

## 주소(라우트)

| 경로 | 화면 | 메뉴 | 로그인 |
|---|---|---|---|
| `/` | 대시보드 | 사이드바·하단 메뉴 | 필요 |
| `/sensors` | 센서 관리 | 사이드바·하단 메뉴 | 필요 |
| `/sensors/new` | 센서 등록 | (센서 관리 하위) | 필요 |
| `/sensors/:sensorId` | 센서 상세 | (센서 관리 하위) | 필요 |
| `/events` | 움직임 기록 | 사이드바·하단 메뉴 | 필요 |
| `/notifications` | 알림 센터 | 사이드바·하단 메뉴 | 필요 |
| `/notifications/:alertId` | 알림 상세 | (알림 센터 하위) | 필요 |
| `/settings` | 설정 | 사이드바 맨 아래·하단 메뉴 | 필요 |
| `/settings/detection` · `/notifications` · `/integrations` · `/data` | 세부 설정 4개 | (설정 하위) | 필요 |
| `/onboarding` | 초기 설정 | 메뉴에 없음 (대시보드 안내에서 진입) | 필요 |
| `/dev/design` · `/dev/simulator` | 개발용 | 설정 하위로 표시 | 필요 |
| `/login` · `/register` · `/notice` | 로그인 · 첫 계정 · 서비스 안내 | — | 필요 없음 |
| `*` | 404 | — | 필요 |

**예전 주소는 새 주소로 넘어갑니다.** `/alerts` → `/notifications`, `/alerts/:id` → `/notifications/:id`, `/history` → `/events`, `/setup` → `/onboarding`. 쿼리(`?…`)와 해시(`#…`)도 그대로 가져가고 `replace`로 이동해 뒤로 가기에 남지 않습니다. 이미 발송된 푸시 알림과 저장해 둔 북마크가 계속 열리게 하기 위한 것입니다. (서비스 워커는 새 주소로 알림을 만듭니다.)

## 한 곳에서 관리하는 것

- `app/paths.ts` — 경로(`PATHS`), 화면 이름(`PAGE_TITLES`), 예전 주소(`LEGACY_PATHS`). 메뉴·링크·탭 제목·이동 경로가 모두 여기 값을 씁니다.
- `app/routes.tsx` — 경로 정의. 각 경로의 `handle`에 화면 이름·상위 화면·본문 너비를 붙입니다. (`RouteHandle`)

### 새 화면 추가하기

1. `paths.ts`에 경로와 이름을 적는다.
2. `routes.tsx`의 `AppShell` `children`에 한 줄을 더하고 `handle({ title })`를 붙인다.
3. 메뉴에 넣을 화면이면 `components/layout/navItems.ts`에 한 줄을 더한다.

탭 제목·스크린리더 안내·이동 경로는 `handle`에서 자동으로 나옵니다.

### 인증 연결

경로는 두 덩어리입니다. **로그인 없이 열리는 화면**(`/login` `/register` `/notice`)과 `RequireAuth` 아래의 모든 화면입니다. 인증 방식을 바꾸거나 권한(보호자/관리자)을 나누려면 `features/auth/RequireAuth.tsx` 한 곳만 고치면 됩니다. 로그인 확인에 실패(서버 오류)했을 때는 로그아웃된 것처럼 로그인 화면으로 보내지 않고 실패를 알립니다.

## 공통 레이아웃 (AppShell)

```
데스크톱·태블릿(768px~)            모바일
┌────────┬────────────────────┐   ┌───────────────────┐
│Sidebar │ Header (고정)      │   │ Header            │
│(고정)  ├────────────────────┤   │  로고·알림·계정   │
│로고    │ 연결 안내          │   │  시스템 상태      │
│메뉴 4  │ 새 알림 배너       │   ├───────────────────┤
│        │ PageContainer      │   │ 연결 안내·배너    │
│        │  Breadcrumbs       │   │ PageContainer     │
│설정    │  화면              │   ├───────────────────┤
│서비스  │                    │   │ MobileNavigation  │
└────────┴────────────────────┘   └───────────────────┘
```

| 구성 요소 | 역할 |
|---|---|
| `AppShell` | 위 틀을 조립. 연결 상태는 `ConnectionProvider`가 한 번만 계산해 아래 요소가 같은 값을 봅니다. |
| `Sidebar` | 고정(스크롤해도 제자리). 로고·핵심 메뉴 4개, 맨 아래 설정과 서비스 안내 |
| `MobileNavigation` | 하단 고정 메뉴 5개(홈·센서·기록·알림·설정), 터치 영역 56px, 아이폰 하단 안전 영역 반영 |
| `Header` | 데스크톱은 위에 붙어 있고(sticky), 모바일은 스크롤과 함께 올라갑니다. 로고(모바일)·시스템 상태·알림 센터 버튼·계정 |
| `ConnectionStatus` | 연결 상태 한 가지를 색·아이콘·글자로 표시 |
| `NotificationTrigger` | 알림 센터로 가는 종 버튼과 확인 전 알림 수 |
| `PageContainer` | 본문 너비·간격, 두 단계 이상일 때 Breadcrumbs |
| `Breadcrumbs` | "설정 > 감지 시간·민감도" 같은 이동 경로. 최상위 화면에는 나오지 않음 |

### 현재 위치 표시

`NavLink`가 `aria-current="page"`를 붙이고, 색뿐 아니라 옅은 알약 모양+점(사이드바)·아이콘 뒤의 알약 모양(하단 메뉴)과 굵은 글씨로 구분합니다. 하위 화면(`/sensors/new`)에서도 상위 메뉴(센서 관리)가 현재 위치입니다. 화면이 바뀌면 탭 제목(`센서 관리 · 노크`)이 바뀌고 스크린리더에도 새 화면 이름을 읽어 줍니다. 새로고침해도 주소가 그대로라 같은 화면이 열립니다.

## 연결 상태 (정상 · 연결 중 · 연결 끊김 · 확인 불가)

`hooks/connection.ts`의 `deriveConnection`(순수 함수)이 인터넷·서버 상태 확인(30초 주기)·실시간 연결을 하나로 합칩니다. 위에서부터 먼저 맞는 것이 결과입니다.

| 조건 | 결과 |
|---|---|
| 브라우저가 인터넷 끊김을 알림 | **연결 끊김** |
| 서버 확인 실패 — 서버에 닿지 못함 | **연결 끊김** |
| 서버 확인 실패 — 서버가 응답했지만 정상이 아님(500, DB 장애 등) | **연결 확인 불가** (서버가 준 설명을 그대로 보여 줌) |
| 실시간 연결이 끊김·실패 | **연결 끊김** |
| 서버 확인 중, 또는 실시간 연결을 만드는 중 | **연결 중** |
| 서버 정상 + 실시간 연결됨 | **연결 정상** |

하나라도 정상이 아니면 "정상"으로 보이지 않습니다.

### 연결이 끊겼을 때 이전 데이터를 현재 상태처럼 보여 주지 않기

- 맨 위 **연결 안내**가 "연결이 끊겨 최신 정보를 받지 못하고 있습니다. 화면의 내용은 ○○까지 확인한 정보이며 지금 상태와 다를 수 있습니다"라고 알립니다. (마지막으로 "연결 정상"이던 시각)
- 헤더의 센서·알림 상태 배지는 "모두 연결됨" 같은 값을 숨기고 "최신이 아니어서 숨겼습니다"로 바뀝니다.
- 알림 센터 버튼의 숫자는 물음표로 바뀝니다. (이전 건수를 현재 값처럼 보여 주지 않음)
- 대시보드는 상태 카드가 "연결 끊김"이 되고 이전 상태는 "마지막으로 확인한 상태: …"로만 덧붙습니다. 자세한 내용은 [DASHBOARD_AND_SENSORS.md](DASHBOARD_AND_SENSORS.md).

**한계:** 센서 목록·움직임 기록·알림 목록 같은 다른 데이터 화면은 이전 데이터를 가리지 않고 그대로 보여 주되, 위 연결 안내가 항상 함께 있습니다. 이 화면들의 개별 행을 "최신 아님"으로 표시하지는 않습니다.

## 미구현 화면

모든 메뉴는 실제 화면에 연결되어 있고, 미구현이어서 비어 있는 화면은 없습니다. (서버에 없는 기능을 Mock으로 쓰는 경우에는 화면에 "샘플 데이터" 표시가 붙습니다.)
