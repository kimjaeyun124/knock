# 온보딩 (초기 설정)

처음 쓰는 보호자가 기술 지식 없이 기본 모니터링 환경을 마련하도록 돕는 6단계 설정입니다. 화면은 `/onboarding`(예전 주소 `/setup`도 넘어옵니다)이고, 모든 값은 **실제 백엔드 API에 저장**됩니다. (Mock·개발용 저장소를 쓰지 않습니다 — 이 기능의 API가 모두 구현되어 있어서입니다.)

## 6단계

| 단계 | 하는 일 | 저장되는 곳 |
|---|---|---|
| 1. 서비스 소개 | 목적·할 수 있는 일·**감지의 한계**를 알리고, 한계를 이해했다고 확인해야 "시작하기"가 켜짐 | 도달 단계(`Household.onboardingStep`) |
| 2. 보호 대상 | 표시 이름(필수, 20자), 메모(선택, 200자), 개인정보 최소 수집 안내 | `CareRecipient.alias` / `memo` |
| 3. 센서 | 등록한 센서 목록(연결·배터리·실제/시뮬레이션 구분), 센서 추가(기존 5단계 등록 안내를 그대로 사용), 연결 상태 다시 확인 | 센서 API(기존) |
| 4. 모니터링 시간 | 시작·종료 시각, 기본 야간 시간(밤 10시~아침 6시) 제안과 되돌리기, 직접 수정 | `DetectionSettings.nightStart` / `nightEnd` |
| 5. 알림 | 받을 움직임 알림 4가지, 센서 이상 알림, 브라우저 알림 안내 | `AlertPreferences`(새로 만듦) |
| 6. 확인 | 저장된 값 요약, 미완료 항목 안내, 설정 완료 | `Household.setupCompletedAt` |

## UX 원칙과 구현

- **현재 단계 표시**: "3/6 단계 · 센서" 글자 + 진행 막대(`role="progressbar"`) + (넓은 화면에서) 단계 목록. 단계가 바뀌면 안내 글자로 초점을 옮겨 스크린리더가 새 단계를 읽습니다.
- **이전 단계 이동·입력값 유지**: 모든 단계에 "이전"이 있고, 입력 중인 값은 화면이 열려 있는 동안 단계를 오가도 남습니다. 저장된 값은 서버에서 다시 읽습니다.
- **필수 입력 검증**: 호칭(1~20자), 메모(200자 이내), 시간(시:분 형식·시작≠종료). 서버도 같은 규칙으로 다시 검증합니다. 오류는 색만이 아니라 글자로 알립니다.
- **가짜 성공 금지**: 센서는 **첫 신호를 받은 뒤에만** "연결됨"으로 표시됩니다. 신호가 없으면 "아직 첫 신호를 받지 못했습니다"라고 하고, 센서가 없거나 신호가 없는 채로도 완료할 수는 있지만 **모니터링되지 않는다고 분명히 알립니다.** 브라우저 알림은 서버·브라우저가 지원하고 실제로 등록된 경우에만 "등록되어 있다"고 표시합니다.
- **큰 버튼·입력 영역**: 모든 조작 요소 높이 44px 이상(E2E가 모바일·데스크톱에서 모든 단계를 검사).

### 3단계 센서
센서 등록 안내(`RegistrationWizard`)를 단계 안에 그대로 넣었습니다. 설치 위치 선택, 실제 장치(장치 토큰)/시뮬레이션 구분, 토큰 한 번만 표시, 연결 확인이 모두 거기서 동작하고, 마지막 버튼만 "센서 화면으로 이동" 대신 온보딩 목록으로 돌아옵니다. 시뮬레이션은 **개발·시연용이며 실제 장치가 아니라고** 목록·요약에 계속 표시됩니다.

### 5단계 알림
| 항목 | 뜻 |
|---|---|
| 현관 근처 움직임 · 침대 주변에서 이동 경로로 이어진 움직임 · 짧은 시간 안의 반복된 움직임 | 해당 유형의 알림을 만들지 여부 |
| 침대 주변 움직임 | 민감도가 "높음"일 때만 만들어지는 알림(기존 규칙). 화면이 그렇게 밝힘 |
| 센서 이상 알림 | 연결 끊김·복구. **꺼도 센서 화면과 대시보드에는 상태가 계속 표시됨** |
| 배터리 부족 알림 | 배터리 부족·위급. 꺼도 센서 화면에는 배터리 상태가 계속 표시됨 |
| (항상 켜짐) 알림 전달 실패 | 끌 수 없음 |

- **끈 종류의 알림은 만들어지지 않습니다.** 움직임 기록은 그대로 남습니다. (`AlertPipeline.raiseIfWanted`)
- 모두 끄면 "화면을 직접 열어야 확인할 수 있다"는 경고를 띄웁니다. 설정 완료 때도 미완료 항목으로 다시 알립니다.
- **브라우저 알림 권한은 버튼을 눌렀을 때만 요청합니다.** 화면을 여는 것만으로 권한 창이 뜨지 않습니다. 허용하지 않아도 계속 진행할 수 있습니다. 서버에 푸시 키가 없으면 "앱 화면이 열려 있을 때만 알림이 보인다"고 알립니다. (실제 푸시 서비스 전달은 기존과 같이 실환경에서 확인하지 못했습니다.)
- 같은 선택을 **설정**(감지·알림 구역)에서 나중에 바꿀 수 있습니다. ([SETTINGS.md](SETTINGS.md))

### 6단계 미완료 항목
저장된 값을 기준으로 계산합니다. (`checklist.ts`, 단위 테스트 있음)

| 수준 | 예 |
|---|---|
| **필수** (완료 버튼이 꺼짐) | 호칭 없음 |
| 경고 (완료 가능) | 센서 없음 · 사용 중인 센서 없음 · 첫 신호를 받은 센서 없음/일부 없음 · 움직임 알림 모두 끔 · 모든 알림 끔 |
| 선택 안내 | 시뮬레이션 센서만 있음 · 이 기기가 푸시에 등록되지 않음 |

각 항목에서 "N단계로 가기"로 바로 돌아갈 수 있습니다.

## 이탈 후 복구

- 단계마다 **"다음"을 누를 때 서버에 저장**하고 도달한 단계(`onboardingStep`, 1~6)도 함께 저장합니다. 도중에 나가거나 다른 기기에서 열어도 그 단계에서 이어 하며 "이전에 하던 곳에서 이어서 합니다"라고 알립니다.
- 단계는 주소(`?step=3`)에 담겨 새로고침·뒤로 가기가 됩니다. **아직 도달하지 않은 단계로는 주소를 바꿔도 건너뛸 수 없습니다.** 도달 단계는 낮아지지 않습니다.
- 저장에 실패하면 그 자리에 머물며 이유를 알리고 입력값을 지우지 않습니다.
- **한계:** 아직 "다음"을 누르지 않은 입력(예: 쓰던 메모)은 화면을 새로고침하면 사라집니다. 브라우저에 임시 저장하지는 않습니다(호칭·메모를 기기에 남기지 않으려는 선택).

## 기존 사용자의 반복 방지

- 설정을 마친 사용자가 `/onboarding`을 열면 단계를 다시 시키지 않고 **"초기 설정을 이미 마쳤습니다"** 와 바꿀 곳(센서 관리·감지 시간·알림 채널)·대시보드 링크를 보여 줍니다. 원하면 "초기 설정 단계를 다시 살펴보기"로 단계를 열 수 있고, 주소로 특정 단계(`?step=4`)를 열 수도 있습니다.
- 대시보드의 "초기 설정을 마치지 않았습니다" 안내는 마치지 않은 사용자에게만 보입니다.
- 마이그레이션(`20261118120000_onboarding`)은 이미 설정을 마친 가구의 도달 단계를 6으로 둡니다.

## API

| 요청 | 설명 |
|---|---|
| `GET/PUT /api/household` | 응답에 `recipientMemo`, `onboardingStep` 추가. PUT은 `recipientAlias`·`recipientMemo`(빈 문자열 = 지움)·`onboardingStep`(1~6, 낮추지 않음)·`completeSetup` |
| `GET/PUT /api/settings/alerts` | 받을 알림(`bedAreaActivity` `bedToPath` `entranceApproach` `repeatedMovement` `sensorIssues`). 모두 보내야 함. 기본값은 모두 true |
| `GET/PUT /api/settings/detection` | (기존) 4단계는 저장된 값에 시간만 바꿔 보냄 |

## 코드 위치

- 화면: `apps/web/src/features/onboarding/` — `OnboardingPage`(불러오기·이미 마침 안내) · `OnboardingWizard`(단계·저장·이어 하기) · `*Step.tsx` · `StepIndicator` · 순수 로직 `steps.ts` `schedule.ts` `checklist.ts`
- 받을 알림 입력·브라우저 알림 안내: `features/settings/AlertPreferenceFields` `AlertPreferencesCard` `BrowserNotificationGuide`
- 서버: `HouseholdService`, `SettingsService.getAlertPreferences/isAlertWanted`, `AlertPipeline.raiseIfWanted`
- 공유: `packages/shared/src/household.ts`(`ONBOARDING_STEP_COUNT`), `settings.ts`(`AlertPreferences*`, `ALERT_PREFERENCE_BY_TYPE`)

## 알려진 한계

- 실제 스크린리더로 읽어 보지 못했습니다. (자동 점검 axe와 키보드까지)
- 센서 등록의 "실제 장치 연결"은 E2E에서 시뮬레이션으로 확인했고, 실제 하드웨어로는 확인하지 못했습니다.
- 알림을 끄는 것은 "만들지 않음"입니다. 이미 만들어진 알림에는 영향이 없고, 끈 동안 생기지 않은 알림은 나중에 되살릴 수 없습니다.
- 계정이 둘 이상인 가구(여러 보호자)는 아직 없어서, 설정은 가구 단위로 하나입니다.
