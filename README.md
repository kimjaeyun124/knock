# 노크

> 이 서비스의 이름은 **노크**입니다. (예전 이름: 테트리스. 내부 패키지 이름 `@tetris/*`·로컬 저장 키 `tetris.*`·로그 이름 `tetris-server` 는 호환을 위해 그대로 둡니다.)

치매 노인 야간 안전 모니터링 및 보호자 알림 서비스.
센서의 움직임 신호를 보호자에게 알려 주는 도구이며, 낙상·배회를 예방하거나 확실히 감지한다고 보장하지 않습니다.

> **현재 상태: Phase 17 완료 — MVP 위에 디자인 시스템(9), 공통 레이아웃·라우팅(10), 대시보드·센서 관리 화면(11), 움직임 기록 타임라인(12), 알림 센터(13), 온보딩(14), 설정 페이지(15), 데이터 모델 점검(16), REST API v1(17)을 더했습니다.** 레이아웃은 [docs/LAYOUT_AND_ROUTING.md](docs/LAYOUT_AND_ROUTING.md), 대시보드·센서 관리는 [docs/DASHBOARD_AND_SENSORS.md](docs/DASHBOARD_AND_SENSORS.md), 움직임 기록은 [docs/EVENTS.md](docs/EVENTS.md), 알림 센터(읽음·전달 상태·실시간)는 [docs/NOTIFICATIONS.md](docs/NOTIFICATIONS.md), 처음 쓰는 보호자의 6단계 초기 설정은 [docs/ONBOARDING.md](docs/ONBOARDING.md), 설정 화면(모니터링·감지·알림·서비스, 어두운 테마)은 [docs/SETTINGS.md](docs/SETTINGS.md), 센서 시뮬레이터(전체 흐름 시연·보안)는 [docs/SIMULATOR.md](docs/SIMULATOR.md), 움직임 판단 규칙(분류·cooldown·시나리오)은 [docs/DETECTION_RULES.md](docs/DETECTION_RULES.md), 실시간 전달(Socket.IO 이벤트·보안·복구)은 [docs/REALTIME.md](docs/REALTIME.md), 센서 상태 모니터링(heartbeat·끊김·배터리·수신 오류)은 [docs/SENSOR_HEALTH.md](docs/SENSOR_HEALTH.md), **실제 센서 연결 구조(어댑터·표준 이벤트·통신 방식 비교; 실제 하드웨어는 미연결)** 는 [docs/HARDWARE_INTEGRATION.md](docs/HARDWARE_INTEGRATION.md), **스마트워치 알림(채널 구조만 구현, 전달은 안 됨)** 은 [docs/WATCH_INTEGRATION.md](docs/WATCH_INTEGRATION.md), 오류 처리·보안 점검과 남은 위험은 [docs/SECURITY_AUDIT.md](docs/SECURITY_AUDIT.md), 발표 시연 방법은 [docs/DEMO_GUIDE.md](docs/DEMO_GUIDE.md), 테스트 결과는 [docs/TEST_REPORT.md](docs/TEST_REPORT.md), 데이터 모델(Prisma·삭제·보존 정책)은 [docs/DATABASE.md](docs/DATABASE.md), 버전이 붙은 REST API(`/api/v1`, 요청·응답 예제)는 [docs/API.md](docs/API.md)에 있습니다. 화면 경로는 `/` `/sensors` `/events` `/notifications` `/settings` `/onboarding`입니다(예전 `/alerts` `/history` `/setup`은 새 주소로 넘어갑니다). 디자인 시스템 문서는 [docs/DESIGN_SYSTEM.md](docs/DESIGN_SYSTEM.md), 실제 모습은 개발 서버의 `/dev/design`(로그인 필요)입니다. 브라우저 E2E(Playwright)가 시뮬레이터로 전체 경로(신호 → 알림 → 화면 → 확인)를 검증하고, 접근성(자동 점검·키보드)과 반응형(데스크톱·태블릿·모바일), 운영 빌드의 보안 정책(CSP)을 확인합니다. **실제 센서와 실제 푸시 서비스(FCM 등)로의 전달은 실환경에서 확인하지 못했습니다.** 운영하려면 [docs/OPERATIONS.md](docs/OPERATIONS.md)의 "운영 전 확인"을 실제 기기로 끝까지 해 보세요. 전체 계획은 [docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md), 문구 기준은 [docs/COPY_GUIDE.md](docs/COPY_GUIDE.md)를 참고하세요.

## 휴대폰 앱 (iOS · Android)

보호자가 알림을 받는 React Native(Expo) 앱이 `mobile/` 에 있습니다. 앱이 실행 중일 때 실시간 연결로 새 알림을 휴대폰 알림(소리·진동)으로 띄우고, 알림 상세에서 확인·종료하고 알림 영상을 재생합니다. 앱을 완전히 닫았을 때 오는 원격 푸시(APNs·FCM)는 아직 없습니다. 실행 방법과 한계는 [docs/MOBILE_APP.md](docs/MOBILE_APP.md), 디자인은 Claude Design 캔버스 "노크 앱·웹 디자인"입니다.

## 실행 환경

| 항목    | 요구 사항                                               |
| ------- | ------------------------------------------------------- |
| Node.js | **24.15 이상** (`.nvmrc`는 `24`). 26.8.2에서 검증       |
| npm     | 10 이상 (11.19.1에서 검증). `engine-strict`가 켜져 있음 |
| OS      | macOS에서 검증. Linux/Windows는 아직 확인하지 않음      |

Node 요구 버전은 Vitest 5, jsdom 31, ESLint 10의 `engines` 조건에서 정했습니다.

## 시작하기

```bash
npm install                 # Prisma 클라이언트도 함께 생성됩니다 (postinstall)
cp .env.example .env
npm run db:deploy           # DB 파일 생성 + 마이그레이션 적용
npm run db:seed             # 데모 가구·보호자 생성 (개발용 가상 데이터)
npm run dev
```

- 웹: <http://localhost:5173> — 로그인 화면이 나옵니다.
- 데모 계정: `demo@example.com` / 비밀번호는 `.env`의 `SEED_DEMO_PASSWORD` 값
- API 서버: <http://127.0.0.1:4000> (헬스체크: <http://localhost:4000/api/health>)

> **첫 계정은 화면에서 만듭니다.** 서버에 보호자가 한 명도 없으면 로그인 화면에 "첫 계정 만들기"가 나타나고, 만들면 바로 로그인되어 초기 설정 마법사로 이어집니다. 보호자가 한 명이라도 있으면 이 경로는 닫히며(403) 누구나 계정을 만들 수 있는 서버가 되지 않습니다. 개발 중에는 시드의 데모 계정(`npm run db:seed`)을 써도 됩니다. 시드는 운영(`NODE_ENV=production`)에서 실행되지 않습니다.

웹 개발 서버는 `/api`와 `/socket.io` 요청을 API 서버로 프록시합니다. 브라우저에서는 항상 같은 출처로 보이므로 개발 중에도 CORS·쿠키 문제가 생기지 않습니다.

서버와 웹을 따로 실행할 수도 있습니다.

```bash
npm run dev:server
npm run dev:web
```

## 센서 신호 보내 보기

실제 센서가 없어도 시뮬레이터로 전체 경로를 시험할 수 있습니다. 시뮬레이터는 실제 센서와 **같은 수집 API(장치 토큰 인증)** 로만 신호를 보냅니다. 서비스 내부를 직접 부르는 지름길이 없으므로, 시뮬레이터로 확인한 경로가 곧 실제 센서의 경로입니다. 수집 규격은 [docs/INGEST_CONTRACT.md](docs/INGEST_CONTRACT.md)입니다.

### 웹 화면 (가장 쉬운 방법)

개발 서버에서는 기본으로 켜져 있습니다. 로그인한 뒤 **설정 → 센서 시뮬레이터**(`/dev/simulator`)를 엽니다. 노트북 카메라 앞에서 직접 움직여 신호를 만드는 **웹캠 움직임 감지**(`/dev/webcam`)도 있습니다. 영상은 브라우저 밖으로 나가지 않고 화면 변화 비율만 계산하며, 사람 인식이 아닙니다([docs/WEBCAM_MOTION.md](docs/WEBCAM_MOTION.md)).

- 구역별 시뮬레이션 센서에 "움직임 보내기", 배터리 값 바꾸기, 연결 끊기·복구
- 시나리오 6종 재생 (배속 1× / 10× / 60×, 중간에 멈추기, 기대하는 결과가 함께 표시됨)
- 장애 주입: 시뮬레이션 알림의 앱 화면 전달 실패 (10분 뒤 자동으로 꺼짐, 실제 알림에는 영향 없음)

야간 시간대가 아니면 움직임 알림은 만들어지지 않고 기록만 남습니다. 화면이 이 사실을 먼저 알려 주며, 알림을 보려면 감지 설정에서 야간 시간대를 지금 시각이 포함되게 바꿔 주세요.

### CLI

```bash
# 시나리오 (보호자 계정으로 로그인합니다. 비밀번호는 환경변수로만 받아 셸 기록에 남지 않습니다)
export TETRIS_EMAIL=<보호자 이메일> TETRIS_PASSWORD=<비밀번호>
npm run sim -- scenarios                              # 목록과 기대하는 결과
npm run sim -- scenario entrance                      # 재생 시작
npm run sim -- scenario bed-to-path --speed 60 --wait # 끝까지 기다림 (실패하면 종료 코드 1, CI에서 사용)
npm run sim -- motion PATH                            # 한 번 움직임 보내기
npm run sim -- fault on                               # 전달 실패 주입 켜기 (off 로 끄기)
npm run sim -- cleanup                                # 시뮬레이션 데이터 모두 삭제

# 장치 흉내 (장치 토큰으로 수집 API 를 직접 호출. 앱의 센서 등록 화면에서 받은 토큰)
export TETRIS_DEVICE_TOKEN=tsn_...     # --token 옵션은 셸 기록에 남으므로 권장하지 않음
npm run sim -- heartbeat --battery 80
npm run sim -- event
npm run sim -- event --id my-test-event-0001   # 같은 ID를 두 번 보내면 DUPLICATE
```

### 시나리오 6종

| id                  | 내용                            | 기대하는 결과                                         |
| ------------------- | ------------------------------- | ----------------------------------------------------- |
| `normal-night`      | 침대 옆 → 이동 경로 → 침대 옆   | 민감도 낮음: 알림 없음 / 보통 이상: "확인 필요" 1건   |
| `bed-to-path`       | 침대 옆 뒤 2분 안에 이동 경로   | 보통 이상: "확인 필요" 1건                            |
| `entrance`          | 현관 센서                       | 모든 민감도에서 "즉시 확인 권장" 1건                  |
| `repeated-movement` | 여러 구역을 번갈아 오감         | "확인 필요"(반복 이동) + 현관 신호의 "즉시 확인 권장" |
| `sensor-trouble`    | 배터리 25→18→9% 후 신호 끊김    | 배터리 알림, 설정한 시간(기본 5분) 뒤 "연결 끊김"     |
| `delivery-failure`  | 전달 실패를 주입한 채 현관 신호 | 약 2분 30초 뒤 "알림을 전달하지 못했습니다"           |

배속은 단계 사이의 기다리는 시간만 줄입니다. 서버가 판단하는 기준 시간(연결 끊김 5분 등)은 그대로입니다.

### 켜고 끄기

`SIMULATOR_ENABLED`(`.env.example` 참고). 지정하지 않으면 개발에서는 켜지고 **운영(`NODE_ENV=production`)에서는 꺼집니다.** 꺼져 있으면 `/api/dev/simulator` 경로가 아예 없고(404) 웹 화면에는 "시뮬레이터가 꺼져 있습니다"만 보입니다. 시뮬레이터가 만든 센서·기록·알림은 `origin=SIMULATED`로 저장되어 화면마다 "시뮬레이션" 배지가 붙고, **설정 → 데이터 관리**(`DELETE /api/data/simulated`)에서 실제 데이터는 그대로 두고 시뮬레이션 데이터만 지울 수 있습니다. 시뮬레이터가 꺼져 있어도 남은 시뮬레이션 데이터는 지울 수 있습니다.

### 장치를 직접 만들어 시험하려면

앱의 **센서 → 센서 등록**에서 센서를 만들고 한 번만 보이는 토큰을 받아 위 "장치 흉내" 명령을 쓰거나, 수집 API(`POST /api/ingest/v1/{events,heartbeat}`)를 직접 호출합니다. 결과는 `GET /api/sensors`(연결 상태·배터리), `GET /api/events`(움직임 기록), `GET /api/alerts`(알림)로도 확인할 수 있습니다.

## 환경변수

`.env.example`을 `.env`로 복사해서 사용합니다. `.env`는 Git에 올리지 않습니다. 서버는 시작할 때 값을 검증하고, 잘못되었으면 한국어 안내와 함께 실행을 중단합니다.

| 변수                 | 대상              | 기본값                  | 설명                                                                                         |
| -------------------- | ----------------- | ----------------------- | -------------------------------------------------------------------------------------------- |
| `SERVER_HOST`        | 서버              | `127.0.0.1`             | 바인딩 주소. 같은 네트워크의 다른 기기에서 접속하려면 `0.0.0.0`                              |
| `SERVER_PORT`        | 서버, 웹 프록시   | `4000`                  | API 서버 포트                                                                                |
| `CLIENT_ORIGIN`      | 서버              | `http://localhost:5173` | Socket.IO CORS 허용 출처. 웹 주소와 같아야 함                                                |
| `LOG_LEVEL`          | 서버              | `info`                  | `fatal`~`trace`, `silent`                                                                    |
| `WEB_PORT`           | 웹 개발 서버      | `5173`                  | 사용 중이면 자동으로 다른 포트로 넘어가지 않고 오류로 종료                                   |
| `VITE_API_BASE_URL`  | **브라우저 공개** | 비어 있음               | 비우면 같은 출처(`/api`) 사용                                                                |
| `VITE_MOCK_FEATURES` | **브라우저 공개** | 비어 있음               | 개발 중 서버에 없는 기능을 샘플 데이터로 바꿈 (아래 "샘플 데이터(Mock)")                     |
| `VITE_APP_MODE`      | **브라우저 공개** | 비어 있음(`api`)        | `api`: 모두 실제 서버 · `demo`: 테스트 데이터 + 데모 모드 표시 (개발 전용, 운영 빌드는 실패) |

**비밀값 취급 규칙**: 브라우저로 전달되는 것은 `VITE_` 접두사 변수뿐입니다. 비밀키·토큰·비밀번호에는 절대 `VITE_`를 붙이지 마세요. 세 겹으로 막혀 있습니다.

1. Vite가 `VITE_` 접두사가 없는 변수를 번들에 넣지 않음
2. ESLint가 `apps/web`, `packages/shared`에서 `process` 사용을 금지
3. `npm run build`가 끝난 뒤 `scripts/check-client-bundle.mjs`가 웹 번들에서 비밀 키 이름과 `.env`의 실제 값을 검색

```

    src/generated/    Prisma 생성 코드 (Git 제외, postinstall로 재생성)
```

- **경로 별칭**: 서버·웹 모두 `@/…` → `src/…`. 워크스페이스 패키지는 `@tetris/shared`.

## 인증과 보안

- **로그인**: 이메일 + 비밀번호. 비밀번호는 Node 내장 scrypt로 해시해 저장합니다(원문 저장 없음).
- **세션**: 브라우저에는 무작위 토큰을 `HttpOnly`, `SameSite=Lax` 쿠키로 주고, DB에는 그 **해시만** 저장합니다. 유효 기간은 14일(연장 없음)이며, 로그아웃하면 서버에서 즉시 폐기됩니다.
- **로그인 시도 제한**: 같은 IP + 이메일로 5번 실패하면 15분간 제한합니다. 이메일만으로 막으면 제3자가 보호자 계정을 일부러 잠글 수 있어 IP를 함께 씁니다. 메모리에 보관하므로 서버를 재시작하면 초기화됩니다. 계정이 없을 때와 비밀번호가 틀렸을 때의 응답 문구·소요 시간을 같게 만들어 가입 여부를 알려 주지 않습니다.
- **CSRF**: 데이터를 바꾸는 요청은 허용된 웹 출처(`CLIENT_ORIGIN` 또는 서버 자신의 출처)에서 온 것만 받습니다.
- **실시간 연결**: 로그인 세션 쿠키가 있어야 연결되고, 웹소켓의 `Origin`도 검사합니다. 로그아웃·세션 만료 시 그 세션의 연결이 끊어집니다.
- **데이터 범위**: 모든 조회·수정은 로그인한 보호자의 가구(`householdId`)로 한정됩니다. 요청 본문의 `householdId`는 무시합니다.
- 리버스 프록시 뒤에서 운영한다면 `TRUST_PROXY`에 프록시 단계 수(보통 `1`)를 지정해야 합니다. 기본값 0이면 `X-Forwarded-For`를 무시해 헤더로 로그인 시도 제한을 피할 수 없고, 프록시 뒤에서 0으로 두면 모든 접속자가 한 IP로 보여 정상 보호자까지 막힐 수 있습니다. 두 동작 모두 서버 테스트가 검증합니다. 자세한 내용은 [운영 가이드](docs/OPERATIONS.md).
- 로그에서는 비밀번호·장치 토큰·쿠키·푸시 키가 가려집니다(`[가려짐]`). 오류 객체나 요청 정보를 통째로 로그에 넘겨도 마찬가지입니다.
- API 응답에는 보안 헤더(helmet)가 붙고, 로그인이 필요한 응답은 `Cache-Control: no-store`입니다. 잘못된 JSON이나 너무 큰 본문도 HTML이나 내부 정보 없이 JSON 오류로 답합니다.

## 알림 규칙과 전달

서비스는 센서의 **움직임 신호를 알려 주는 도구**입니다. 낙상·배회를 확실히 감지하거나 예방하지 않으며, 모든 알림 문구는 "감지되었습니다 + 확인해 주세요" 형태입니다. (`packages/shared`의 `FORBIDDEN_PHRASES` 검사가 테스트로 강제합니다)

### 규칙 (야간 시간대, 한국 시각 기준)

| 알림                     | 조건                                                                          | 수준      |
| ------------------------ | ----------------------------------------------------------------------------- | --------- |
| 현관 근처 움직임         | 현관 신호 (모든 민감도)                                                       | 긴급      |
| 침대 주변 → 이동 경로    | 침대 주변 신호 뒤 설정 시간(기본 10분) 안에 이동 경로 신호 (민감도 보통 이상) | 주의      |
| 침대 주변 움직임         | 침대 주변 신호 하나 (민감도 높음만)                                           | 주의      |
| 짧은 시간 안의 반복 이동 | 30분 안에 구역이 바뀐 횟수 낮음 6 / 보통 4 / 높음 3                           | 주의      |
| 센서 연결 끊김           | 설정 시간(기본 5분) 신호 없음. 그 구역의 유일한 센서면 긴급, 아니면 주의      | 긴급/주의 |
| 센서 배터리              | 부족(기본 20%) 정보 → 위급(10%) 주의로 격상                                   | 정보/주의 |
| 알림 전달 실패           | 알림을 어떤 채널로도 전달하지 못함                                            | 긴급      |

- 야간 여부는 신호가 **발생한 시각**으로 판단합니다. 낮에 생긴 신호는 기록만 하고 알리지 않습니다. 늦게 도착한 신호가 근거에 있으면 문구에 그 사실을 밝힙니다.
- 실제 센서와 시뮬레이터 신호는 서로 섞어서 판단하지 않습니다.
- 규칙은 `apps/server/src/domain/rules/`의 **순수 함수**라서 시계·DB 없이 테스트할 수 있습니다. 임계값은 초기값이며 시뮬레이터와 현장 검증으로 조정해야 합니다.

### 알림의 생애

1. **생성·합치기**: 같은 종류의 움직임 알림이 반복 억제 시간(기본 10분) 안에 다시 생기면 새 알림 없이 근거 신호만 더합니다. 보호자가 종료한 뒤의 신호는 새 알림입니다. 연결 끊김·배터리는 센서마다 알림 하나를 상태가 풀릴 때까지 유지합니다.
2. **격상**: 더 높은 수준의 후보가 합쳐지면(예: 배터리 부족 → 위급) 알림을 격상하고 다시 확인이 필요한 상태로 되돌립니다.
3. **확인·종료**: `POST /api/alerts/:id/acknowledge`, `.../resolve`(결과: 확인함/잘못된 알림 + 메모). 센서가 복구되는 등 조건이 풀리면 시스템이 `자동 종료`합니다.
4. **재알림**: 확인하지 않은 긴급 알림은 설정 간격(기본 5분)마다 최대 3번 다시 알립니다.
5. **읽음**: 보호자가 알림을 봤다는 표시(`POST /api/alerts/:id/read`, `/read-all`)는 보호자마다 따로 저장되며 **확인·종료와 별개**입니다. 읽어도 해결된 것이 아닙니다. 끊겼던 센서가 돌아오면 "연결 복구" 정보 알림이 만들어집니다. 자세히는 [docs/NOTIFICATIONS.md](docs/NOTIFICATIONS.md).

### 전달 (보호자 × 채널마다 전달 기록을 남김)

| 채널            | 현재 상태                                                                                                                                                                                   |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 앱 화면(IN_APP) | **실연동.** 보호자의 앱 화면이 **열려 있을 때만** 전달됩니다.                                                                                                                               |
| 브라우저 푸시   | **서버에 VAPID 키를 설정한 때만 실연동.** 설정하지 않으면 `NOT_CONFIGURED`입니다. 보호자가 기기를 등록해야 하며(설정 → 알림 채널), 등록한 기기가 없거나 모두 실패하면 전달 실패로 남깁니다. |
| 문자·카카오     | **연동하지 않았습니다.** 보낸 척하지 않고 `NOT_CONFIGURED`로 기록합니다. (외부 사업자 계약 필요)                                                                                            |

- 앱 화면이 열려 있지 않으면 전달 성공으로 기록하지 않습니다. 30초·2분 뒤 다시 시도하고(총 3번), 그동안 보호자가 앱을 열면 전달됩니다. 끝내 실패하면 **"알림을 전달하지 못했습니다" 긴급 알림**을 남깁니다. 한 명이라도 받았으면 실패로 보지 않습니다.
- ⚠️ **푸시를 설정하지 않았다면 잠든 보호자를 깨울 방법이 없습니다.** 앱을 열어 두지 않았다면 알림은 다음에 앱을 열었을 때 목록에서 보입니다. 이 한계는 홈(푸시 미설정 시 항상), 알림 상세, 알림 채널 화면, `/notice`에 분명히 밝혀 둡니다. 푸시를 설정해도 **휴대폰이 꺼져 있거나 푸시 서비스에 닿지 못하면 전달되지 않을 수 있으며**, iPhone·iPad는 홈 화면에 추가한 웹앱에서만 받을 수 있습니다.
- 정보(INFO) 수준 알림(배터리 부족)은 목록에만 올라가고 별도 알림을 보내지 않습니다.
- 시뮬레이터가 만든 알림은 앱 밖으로 나가는 채널로 보내지 않습니다.

### 주기 점검 (30초마다)

신호가 끊긴 센서 찾기 → 해소된 시스템 알림 자동 종료 → 알림 전달 재시도 → 긴급 알림 재알림 → (1시간마다) 보관 기간(기본 90일)이 지난 움직임 기록·종료된 알림·센서 이력 삭제. 한 단계가 실패해도 나머지는 계속 실행됩니다.

### 실시간 이벤트 (Socket.IO, 로그인 필요)

`event.created` · `alert.created` · `alert.updated` · `alert.notify`(해당 보호자 화면에만) · `sensor.status` · `delivery.updated` · `settings.updated`. 소켓은 화면을 빨리 갱신하기 위한 수단일 뿐이므로, 화면은 다시 연결될 때 REST로 목록을 다시 가져와 놓친 것을 보충해야 합니다. 알림 판단은 같은 가구의 변경을 한 번에 하나씩 처리하므로 신호가 동시에 들어와도 알림이 중복으로 생기지 않습니다. (서버 프로세스 하나 기준이며, 여러 대로 늘리면 DB 수준 잠금이 필요합니다)

## 센서 수집 API 보안

- **장치 토큰**: 센서마다 `tsn_` 로 시작하는 무작위 256비트 토큰을 발급하고, 서버에는 **해시만** 저장합니다. 원문은 등록·재발급 응답에서 한 번만 보여 줍니다. 재발급하면 이전 토큰은 즉시 무효입니다.
- 사용자용 API(쿠키)와 장치용 API(Bearer 토큰)는 **서로 다른 인증**입니다. 쿠키로 수집 API를, 장치 토큰으로 사용자용 API를 쓸 수 없습니다.
- 구역·출처(실제/시뮬레이션)는 장치가 보내지 않고 등록된 센서 정보에서 정해집니다. 요청 본문에 끼워 넣어도 무시됩니다.
- 센서당 분당 120회로 제한합니다. 잘못된 토큰은 IP로 차단하지 않고 거부만 합니다. (같은 공유기의 정상 센서가 함께 막히는 일을 피하기 위해서이며, 토큰이 추측 불가능한 값이라 차단 없이도 안전합니다.)
- 센서를 삭제하면 그 센서의 움직임 기록도 함께 지워지므로, 먼저 "사용 안 함"으로 끈 센서만 삭제할 수 있습니다.
- 이벤트 ID가 같은 중복 전송은 몇 번이든 한 번만 저장됩니다. 늦게 도착한 이벤트(2분 이상)는 버리지 않고 "지연 수신"으로 표시합니다.

## 오류 처리 원칙

- **서버**: 모든 오류를 `{ "error": { "code", "message", "requestId" } }` 형식(한국어 메시지)으로 응답합니다. 예상하지 못한 오류는 500과 일반 안내문만 내려 보내고, 내부 내용은 로그에만 남깁니다. 없는 API 경로는 HTML이 아니라 JSON 404입니다.
- **웹**: 모든 API 호출은 `services/apiClient.ts`를 거칩니다. 성공은 "2xx 상태이고 응답이 공유 스키마와 일치할 때"만 인정합니다. 연결 실패, 오류 상태(프록시의 502 포함), HTML이 돌아온 경우, 형식이 다른 응답은 모두 오류로 처리되어 화면에 표시됩니다.
- 이전에 성공한 응답이 남아 있어도, 가장 최근 확인이 실패했으면 "서버 연결됨"을 표시하지 않습니다.
- 상단 상태 띠가 서버 연결과 실시간 연결 상태를 항상 보여 줍니다. 홈 화면의 "서버 연결됨"은 서버가 응답한다는 뜻이며 어르신의 상태와는 무관합니다.

## 웹 화면의 상태 표시

- **헤더의 시스템 상태**(모든 화면): **연결 정상 / 연결 중 / 연결 끊김 / 연결 확인 불가** 네 가지 중 하나(인터넷·서버·실시간 연결을 합친 값), 센서(연결 끊김·첫 신호 대기·시뮬레이션), 알림 전달 실패, 샘플 데이터 사용 여부. 센서나 알림을 불러오지 못하면 "정상"이 아니라 "확인하지 못했습니다"로 표시합니다.
- **연결이 끊기면** 맨 위에 "최신 정보를 받지 못하고 있습니다 — 화면의 내용은 ○○까지 확인한 정보"라는 안내가 붙고, 센서 배지·알림 건수·대시보드 상태 카드는 이전 값을 현재 값처럼 보여 주지 않습니다. 자세히는 [docs/LAYOUT_AND_ROUTING.md](docs/LAYOUT_AND_ROUTING.md).
- **대시보드의 큰 상태**: 정상 / 주의 / 확인 필요(긴급이면 "즉시 확인 권장" 함께) / 연결 끊김 / 상태 확인 불가. 센서가 없거나 끊겼거나 첫 신호를 기다리면 "정상"이라고 하지 않고, 정상일 때도 "최근 감지된 주의 이벤트가 없습니다"처럼 관측한 사실로만 말합니다. 화면 상태는 Loading·Success·Empty·Error·Offline 다섯 가지입니다. 자세히는 [docs/DASHBOARD_AND_SENSORS.md](docs/DASHBOARD_AND_SENSORS.md).
- 실시간 이벤트(`alert.*`, `event.created`, `sensor.status` 등)는 "바뀌었다"는 신호로만 쓰고 내용은 서버 API로 다시 읽습니다. 연결될 때마다 전부 다시 읽어 끊긴 동안의 변화를 보충하고, 연결이 끊기면 즉시 다시 확인합니다.
- 상태는 색 + 아이콘 + 글자로 전달하며, 디자인 토큰의 글자·배경 대비(WCAG AA)는 테스트가 검사합니다.

## 브라우저 푸시 (선택)

앱 화면을 닫아 둔 보호자에게 알림을 보내려면 브라우저 푸시를 켭니다. 서버에 VAPID 키가 없으면 푸시 채널은 "연동되지 않음"으로 표시되고 아무것도 보내지 않습니다.

```bash
npm run vapid:generate    # VAPID 키 쌍을 만들어 .env 에 붙여 넣을 형식으로 출력합니다
# 출력된 VAPID_PUBLIC_KEY / VAPID_PRIVATE_KEY / VAPID_SUBJECT 를 .env 에 넣고 서버를 다시 시작합니다.
# VAPID_SUBJECT 는 운영자 연락처(mailto: 또는 https://)로 직접 채워 주세요.
```

- **VAPID_PRIVATE_KEY 는 서버 전용 비밀값입니다.** 저장소에 올리거나 다른 사람에게 보내지 마세요. (웹 번들 검사가 비밀 키 이름과 `.env` 의 실제 값을 찾아 새는지 확인합니다.) 세 값은 모두 지정하거나 모두 비워야 하며, 일부만 있으면 서버가 시작하지 않습니다.
- 보호자가 **설정 → 알림 채널 → "이 기기에서 푸시 받기"** 로 기기를 등록합니다. 브라우저가 알림 권한을 묻고, 허용하면 서비스 워커(`/sw.js`)가 등록됩니다. 기기는 보호자당 최대 10개이며 본인 것만 보고 지울 수 있습니다.
- 푸시로 가는 내용은 알림 제목과 "앱에서 확인해 주세요."뿐이며 센서 ID 같은 내부 정보는 담지 않습니다. 알림을 누르면 해당 알림 화면이 열립니다. 푸시는 푸시 서비스(브라우저 제조사)를 거쳐 암호화되어 전달됩니다.
- 푸시 서비스 주소는 서버가 직접 요청을 보내는 곳이므로 `https` 도메인만 받습니다. IP 주소, localhost, 사설망 이름, 포트 지정 주소는 거부합니다. (도메인이 나중에 내부 IP로 바뀌는 DNS 재바인딩까지는 막지 못합니다.)
- 푸시 서비스가 구독이 만료됐다고(404/410) 답하면 그 기기는 목록에서 자동으로 지웁니다. 그 밖의 실패는 지우지 않고 전달 실패로 남깁니다.
- 시뮬레이터가 만든 알림은 푸시로 보내지 않습니다.
- **채널 테스트**: 설정 → 알림 채널에서 채널마다 "테스트 보내기"를 누를 수 있습니다. 알림이나 전달 기록은 만들지 않으며, 앱 화면 채널은 서버가 보냈다는 것만으로는 성공으로 보지 않고 **이 화면에 실제로 도착했을 때** 도착했다고 알립니다. 같은 채널은 5초에 한 번만 보낼 수 있습니다. "마지막 전달 성공 시각"은 실제 알림의 전달 기록과 테스트 발송을 합친 값이며, 서버를 다시 시작하면 테스트 발송 기록은 사라집니다.

## 샘플 데이터(Mock)

화면은 `useApi()`로만 서버와 통신하고, 기능마다 **실제 서버**와 **Mock** 중 구현을 고를 수 있습니다. 서버에 이미 있는 기능은 모두 실제 서버를 씁니다. 연동 현황(`integrations`)은 이제 서버가 제공하며, 그 Mock은 "가짜 응답" 같은 실제 서버로는 만들기 어려운 상태를 화면에서 미리 볼 때만 씁니다.

```bash
# .env — 개발 중에만. 켜면 상단에 "일부 화면이 샘플 데이터입니다"가 표시됩니다.
# integrations: 가짜 응답 채널 / dashboard: 대시보드 예시 데이터((샘플) 표시) / sensors: 메모리 속 센서 API / timeline: 움직임 기록 예시 데이터
VITE_MOCK_FEATURES=integrations,dashboard,sensors,timeline
```

- Mock을 켜지 않으면 항상 실제 서버를 호출하며, 서버가 응답하지 못하면 가짜 목록 대신 오류를 보여 줍니다. (서버에 없는 기능을 부르면 `not-implemented` 오류로 "아직 구현되지 않은 기능"이라고 표시하는 장치는 남아 있습니다.)
- `health`(서버 상태)와 `auth`(로그인)는 Mock으로 바꿀 수 없습니다. 알 수 없는 이름이나 Mock이 없는 기능을 적으면 앱이 시작하지 않고 이유를 알려 줍니다.
- **운영 빌드에는 Mock이 들어가지 않습니다.** `VITE_MOCK_FEATURES`가 비어 있지 않으면 `npm run build`가 실패하고, 빌드 뒤 번들 검사가 Mock 표식을 한 번 더 찾습니다.

웹이 서버와 연결되는 구조·연결 오류 안내·API/Demo 모드 상세는 [docs/FRONTEND_API.md](docs/FRONTEND_API.md)에 있습니다. `VITE_APP_MODE=demo`로 데모 모드(테스트 데이터, 모든 화면에 표시)를 켤 수 있고 운영 빌드에서는 거부됩니다.

## E2E 테스트 (Playwright)

실제 서버(임시 SQLite)와 웹 개발 서버를 띄우고, 이미 설치된 **Google Chrome**으로 전체 경로를 확인합니다. 브라우저를 따로 내려받지 않습니다. 신호는 시뮬레이터가 실제 수집 API로 보냅니다.

```bash
npm run e2e                                         # 전체 (약 10~15분)
npx playwright test -c e2e --project=desktop flows  # 시나리오만
npx playwright test -c e2e a11y keyboard responsive # 접근성·키보드·반응형 (약 3분)
npx playwright show-report e2e/playwright-report    # 실패했을 때 화면·트레이스 보기
```

- 서버는 `4100`, 웹은 `5273`, 운영 빌드 미리보기는 `5274` 포트를 씁니다. 개발 서버(4000/5173)와 겹치지 않고, 개발 DB(`dev.db`)와 `.env`는 건드리지 않습니다. 계정은 실행마다 새로 만든 임의의 가상 계정입니다.
- 서버 상태를 모든 테스트가 공유하므로 한 번에 하나씩 실행합니다.

## 성능

센서 3개가 90일 동안 쉬지 않고 신호를 보낸 매우 바쁜 경우(움직임 기록 15만 건, 알림 3천 건)를 가정해 SQLite에서 서비스 계층의 조회 시간을 한 번 측정했습니다. (일회성 측정이며 테스트로 남기지는 않았습니다. 개발 PC 한 대, 서버 계층만 잰 값이라 네트워크 시간은 빠져 있습니다)

| 조회                               | 중앙값 / p95  |
| ---------------------------------- | ------------- |
| 움직임 기록 최근 24시간 (200건)    | 1.6ms / 2.4ms |
| 움직임 기록 첫 쪽 (50건)           | 0.5ms / 3.2ms |
| 움직임 기록 구역+센서 필터 (200건) | 1.3ms / 1.6ms |
| 진행 중 알림 (100건)               | 0.6ms / 0.8ms |
| 알림 첫 쪽 (30건)                  | 1.1ms / 4.2ms |
| 센서 목록                          | 0.2ms / 0.6ms |
| 주기 점검 1회                      | 3.1ms / 3.7ms |
| 30일 지난 기록 약 10만 건 삭제     | 0.5초         |

웹은 처음 화면(로그인·홈·설정 목록) 외의 화면을 들어갈 때 불러옵니다. 처음 내려받는 자바스크립트가 608kB(gzip 182kB)에서 399kB(gzip 125kB)로 줄었고 빌드 크기 경고가 사라졌습니다.

## 알아 둘 점

- **TypeScript는 6.0.x에 고정**했습니다. 최신 7.0.2는 `typescript-eslint`(peer `typescript <6.1.0`)와 맞지 않아서입니다. typescript-eslint가 7을 지원하면 올립니다.
- Prisma는 이후 단계에서 **7.10.1 안정 버전으로 고정**해 설치합니다. npm `latest` 태그가 RC(8.0.0-rc)이기 때문입니다.
- `npm audit`는 개발 도구(ESLint → minimatch)에서 moderate 10건을 보고합니다. 운영 의존성은 0건(`npm audit --omit=dev`)이며, 수정안이 ESLint 9로의 다운그레이드라서 적용하지 않았습니다.
- npm 11이 `esbuild`의 postinstall 스크립트 미승인 경고를 냅니다. 실행에는 영향이 없습니다(플랫폼별 바이너리 패키지로 설치됨).
- 폰트는 시스템 한글 폰트(Apple SD Gothic Neo, Noto Sans KR, 맑은 고딕)를 씁니다. Pretendard는 패키지가 매우 커서 도입하지 않았고, 나중에 필요한 글꼴 파일만 자체 호스팅합니다.
- 서버 헬스체크(`/api/health`)는 DB 점검까지 합니다. DB를 쓸 수 없으면 "정상" 대신 503과 안내 문구를 돌려줍니다.
- 스키마를 바꾸면 `npm run db:migrate`로 마이그레이션을 만들고 생성된 `prisma/migrations/`를 함께 커밋합니다.
- 아직 없는 것: 문자·카카오 연동(외부 사업자 계약 필요), 실제 스크린리더로 읽어 보는 점검. 계정 추가·비밀번호 변경은 MVP에서 제외했습니다. 순서는 계획서를 따릅니다.
- **알림 소리**는 기본이 꺼져 있고(상단 "알림 소리" 버튼) 이 브라우저에만 저장됩니다. 브라우저 정책상 화면을 한 번 조작한 뒤에만 소리가 납니다. 앱 화면 알림은 화면이 열려 있을 때만 전달됩니다.
- 센서의 **장치 토큰은 등록·재발급 직후 한 번만** 보입니다. 화면은 토큰을 저장소나 주소에 남기지 않습니다.
- 모바일에서는 상단 상태 띠가 여러 줄로 늘어나 화면 높이를 꽤 차지합니다. 경고를 화면 밖으로 숨기지 않기 위해 줄바꿈을 택했고, 더 줄이는 것은 앞으로의 과제입니다.
